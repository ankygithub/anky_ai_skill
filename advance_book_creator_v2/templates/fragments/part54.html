第五十四章 AI Agent平台与智能体编排——创建Agent的最小功能集

9.3 角色设定、工作流与工具配置

创建一个可用的Agent不需要从零开始搭建所有能力。本节定义创建Agent的最小功能集，涵盖角色设定、工作流设定、工具配置、记忆机制和受监督边界五个核心维度。

9.3.1 角色设定：人设与边界

角色设定是Agent的"灵魂"。它定义了Agent是谁、做什么、不做什么。一个清晰的角色设定能够避免Agent在复杂场景中出现行为不一致或越权操作。 角色设定的核心要素
要素说明示例
人设Agent的身份定位和沟通风格"你是一位资深法务顾问，擅长合同审查和风险评估"
职责范围Agent能够处理的任务类型"你负责采购合同的审查，包括条款抽取、风险识别和修改建议"
不可越界规则明确Agent不能做的事情"你不能修改合同条款、不能代替人工审批、不能对外发送法律意见"
权限等级Agent能够访问的系统和数据"你可以访问合同管理系统和法规知识库，不能访问财务系统"
升级规则什么情况下需要转交人工"当发现高风险条款或置信度低于70%时，转交法务专员处理"
角色设定示例 
agent_role:
  name: "contract_reviewer_agent"
  display_name: "合同审查助手"
  persona: |
    你是一位资深法务顾问，拥有10年合同审查经验。
    你擅长识别合同中的风险条款，并提供专业的修改建议。
    你的沟通风格专业、严谨、客观。
  
  responsibilities:
    - "审查采购合同、销售合同和服务合同"
    - "识别风险条款并提供修改建议"
    - "比对合同与企业标准模板的差异"
    - "生成合同审查报告"
  
  boundaries:
    - "不得修改合同原文"
    - "不得代替人工审批"
    - "不得对外发送法律意见"
    - "不得访问与合同审查无关的系统"
  
  permissions:
    allowed_systems:
      - "合同管理系统（只读）"
      - "法规知识库（只读）"
      - "企业标准模板库（只读）"
    restricted_systems:
      - "财务系统"
      - "人事系统"
      - "审批系统"
  
  escalation_rules:
    - "发现高风险条款（critical/high）→ 转交法务专员"
    - "字段置信度 < 70% → 转交人工复核"
    - "合同金额 > 1000万 → 转交高级法务"
    - "涉及跨境交易 → 转交涉外法务"

⚠️ 关键提醒： 角色设定中的"不可越界规则"是Agent安全性的基石。每条规则都必须是明确的、可执行的，不能出现模糊表述。

9.3.2 工作流设定：问题分类与执行编排

工作流设定定义了Agent处理任务的流程逻辑。一个结构化的工作流确保Agent能够按正确的顺序执行操作，避免遗漏关键步骤。 工作流核心要素
要素说明
问题分类器将用户输入分类到不同的处理流程
触发条件每个流程节点的启动条件
执行顺序流程节点的执行顺序和依赖关系
模型输出每个节点的预期输出
终止条件流程结束的条件
可视化工作流配置

现代Agent平台通常提供可视化的工作流配置界面，用户可以通过拖拽组件来构建工作流：

workflow:
  name: "contract_review_workflow"
  
  nodes:
    - id: "input"
      type: "user_input"
      description: "接收用户上传的合同文档"
    
    - id: "classify"
      type: "classifier"
      description: "合同类型分类"
      categories: ["purchase_contract", "sales_contract", "service_contract", "other"]
      next:
        - condition: "purchase_contract" → "purchase_review"
        - condition: "sales_contract" → "sales_review"
        - condition: "service_contract" → "service_review"
        - condition: "other" → "manual_review"
    
    - id: "purchase_review"
      type: "parallel"
      description: "采购合同审查"
      branches:
        - "field_extraction"   # 字段抽取
        - "risk_analysis"      # 风险分析
        - "template_comparison" # 模板比对
      next: "merge_results"
    
    - id: "field_extraction"
      type: "tool_call"
      tool: "contract_field_extractor"
      output: "extracted_fields"
    
    - id: "risk_analysis"
      type: "llm_call"
      prompt: "risk_analysis_prompt"
      output: "risk_items"
    
    - id: "template_comparison"
      type: "tool_call"
      tool: "template_comparator"
      output: "comparison_result"
    
    - id: "merge_results"
      type: "merge"
      inputs: ["extracted_fields", "risk_items", "comparison_result"]
      output: "review_result"
    
    - id: "escalation_check"
      type: "condition"
      condition: "has_critical_risk OR low_confidence_fields > 3"
      next:
        - condition: "true" → "escalate_to_human"
        - condition: "false" → "generate_report"
    
    - id: "generate_report"
      type: "llm_call"
      prompt: "report_generation_prompt"
      output: "review_report"
    
    - id: "escalate_to_human"
      type: "escalation"
      assign_to: "legal_reviewer"
      reason: "高风险或低置信度需要人工处理"
    
  output: "review_report"

9.3.3 工具配置：通用/行业/内部系统

Agent的核心能力之一是调用工具。工具配置需要按类型分级管理：

工具类型说明示例风险等级
通用工具所有Agent都可使用的基础工具搜索、计算器、翻译、时间转换低
行业工具特定行业的专业工具法规查询、票据验真、信用查询中
内部系统工具企业内部系统的API接口合同管理系统、OA系统、ERP系统高
工具配置示例 
tools:
  - id: "knowledge_search"
    name: "知识检索"
    type: "general"
    description: "从企业知识库中检索相关信息"
    risk_level: "low"
    requires_human_confirmation: false
  
  - id: "regulation_query"
    name: "法规查询"
    type: "industry"
    description: "查询相关法规条款和司法解释"
    risk_level: "medium"
    requires_human_confirmation: false
  
  - id: "contract_query"
    name: "合同查询"
    type: "internal"
    description: "查询合同管理系统中的合同信息"
    risk_level: "low"
    requires_human_confirmation: false
  
  - id: "contract_submit"
    name: "合同提交"
    type: "internal"
    description: "将审查后的合同提交到审批流程"
    risk_level: "high"
    requires_human_confirmation: true

9.3.4 记忆机制：脉络记忆与跨会话学习

记忆机制是Agent从"一次性工具"进化为"持续进化的助手"的关键。记忆分为三个层次：
记忆层次说明实现方式
短期上下文当前对话的上下文对话历史，窗口大小可配置
长期向量记忆历史交互的语义存储向量数据库，语义相似度检索
脉络记忆跨会话的上下文学习和偏好记忆LangMem/Memobase/A-MEM
脉络记忆（Contextual Memory）

脉络记忆是Agent记忆机制的核心创新，它使得Agent能够：

  • 记住用户的偏好和历史交互模式
  • 跨会话学习，持续优化判断标准
  • 理解上下文中的隐含信息

主流脉络记忆方案对比：

方案特点适用场景
LangMemLangChain生态，与LangGraph深度集成LangChain/LangGraph项目
Memobase专为Agent设计的记忆数据库，支持语义检索和时序记忆复杂Agent项目
A-MEM异步记忆管理，支持大规模并发高并发Agent场景
记忆配置示例 
memory:
  short_term:
    type: "conversation_history"
    max_turns: 20
    max_tokens: 4000
  
  long_term:
    type: "vector_store"
    store: "milvus"
    embedding_model: "bge-large-zh"
    collection: "agent_memory"
  
  contextual:
    type: "memobase"
    store_endpoint: "http://memobase-server:8080"
    learning_rate: 0.01
    retention_days: 90
    categories:
      - "user_preferences"
      - "review_patterns"
      - "common_corrections"

9.3.5 受监督边界：关键动作人工确认

Agent的受监督边界定义了哪些操作需要人工确认后才能执行。这是防止Agent失控的关键安全机制。

人工确认规则
操作类型确认要求示例
只读操作无需确认查询数据、检索知识、分析文档
低风险写操作事后通知生成报告、创建草稿、标记标签
中风险写操作事前确认提交审批、发送邮件、修改配置
高风险写操作事前确认+双人复核支付操作、合同签署、数据删除
边界配置示例 
supervision:
  auto_execute:
    - "knowledge_search"
    - "document_analysis"
    - "report_generation"
  
  require_confirmation:
    - "contract_submit"
    - "email_send"
    - "configuration_change"
  
  require_dual_approval:
    - "payment_execute"
    - "contract_sign"
    - "data_delete"
  
  escalation_thresholds:
    - "contract_amount > 10000000"
    - "risk_level = critical"
    - "confidence < 0.50"

9.3.6 最小功能集检查清单

创建Agent时，以下功能集是必须配置的：

  • [ ] 角色设定：人设、职责范围、不可越界规则、权限等级、升级规则
  • [ ] 工作流设定：问题分类器、触发条件、执行顺序、模型输出、终止条件
  • [ ] 工具配置：通用工具、行业工具、内部系统工具
  • [ ] 记忆机制：短期上下文、长期向量记忆、脉络记忆
  • [ ] 受监督边界：只读操作、低风险、中风险、高风险操作的确认规则

9.3.7 本章小结

创建Agent的最小功能集包含角色设定、工作流设定、工具配置、记忆机制和受监督边界五个维度。角色设定定义了Agent的人设和不可越界规则；工作流设定通过问题分类器和执行编排确保流程正确；工具配置按通用/行业/内部系统三级管理；记忆机制从短期上下文到脉络记忆实现持续进化；受监督边界确保关键操作必须经过人工确认。这些功能集是Agent从概念到可用的必要条件。
