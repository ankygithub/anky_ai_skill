第四十一章 智能问数——指标语义层与Text-to-SQL安全

7.5 指标语义层建设与Text-to-SQL安全机制

指标语义层是智能问数系统的核心中枢，Text-to-SQL安全是保障数据不被错误查询的关键防线。本节从语义层建设和SQL安全两个维度深入展开。

7.5.1 指标语义层建设

指标语义层（Semantic Layer）是将业务语言翻译为数据语言的桥梁。它不仅仅是一个字典或映射表，而是一个包含指标定义、维度体系、同义词库和业务词典的完整知识体系。 语义层四大核心组件 组件一：指标字典（Metric Dictionary）

指标字典是语义层的核心，定义企业中所有指标的计算逻辑和业务含义。

字段说明示例

维度字典定义数据的所有分析维度及其层级关系。

同义词匹配策略：

def resolve_term(user_input: str) -> Optional[MetricOrDimension]:
    """将用户输入映射为标准指标或维度"""
    # 精确匹配
    if user_input in synonym_index:
        return synonym_index[user_input].standard_term

    # 模糊匹配（编辑距离）
    candidates = fuzzy_match(user_input, synonym_index.keys(), threshold=0.8)
    if len(candidates) == 1:
        return synonym_index[candidates[0]].standard_term
    elif len(candidates) > 1:
        # 多个候选项，请求用户确认
        return disambiguate(user_input, candidates)

    return None

7.5.2 Text-to-SQL安全机制

Text-to-SQL是智能问数的核心技术之一，但也是安全风险最高的环节。必须建立多层安全防护机制。

🔴 安全铁律： 不要让大模型直接连接生产数据库自由查询。所有SQL必须经过语义层生成查询计划，再通过SQL校验器检查后才能执行。

校验器实现示例 
class SQLValidator:
    """SQL校验器"""

    def validate(self, sql: str, user_context: UserContext) -> ValidationResult:
        """对SQL进行多维度校验"""
        parsed = self.parse_sql(sql)

        # 检查1: 表权限
        table_check = self.check_table_permissions(parsed.tables, user_context)
        if not table_check.passed:
            return ValidationResult.fail("无权限访问表: " + ", ".join(table_check.denied_tables))

        # 检查2: 字段权限
        field_check = self.check_field_permissions(parsed.fields, user_context)
        if not field_check.passed:
            # 自动替换为脱敏版本
            sql = self.apply_field_masking(sql, field_check.masked_fields)

        # 检查3: 扫描量预估
        scan_check = self.estimate_scan_volume(sql)
        if scan_check.exceeds_limit:
            return ValidationResult.fail(
                f"预估扫描{scan_check.rows}行，超过{scan_check.limit}行限制。请缩小时间范围。"
            )

        # 检查4: 聚合逻辑
        agg_check = self.check_aggregation_logic(parsed)
        if not agg_check.passed:
            return ValidationResult.warn(f"聚合逻辑问题: {agg_check.message}")

        # 检查5: 时间范围
        time_check = self.check_time_range(sql)
        if time_check.exceeds_limit:
            return ValidationResult.warn(
                f"查询时间跨度{time_check.days}天，建议不超过90天。"
            )

        # 检查6: 敏感字段
        sensitive_check = self.check_sensitive_fields(parsed, user_context)
        if not sensitive_check.passed:
            sql = self.apply_sensitive_masking(sql, sensitive_check.fields)

        return ValidationResult.pass(sql)

7.5.3 查询计划生成

查询计划（Query Plan）是语义层生成的结构化查询描述，而非直接的SQL。这样做的好处是：

  1. 口径一致性：查询计划基于预定义的指标和维度生成，确保每次查询使用相同的计算逻辑
  2. 安全性：查询计划不包含具体的表名和字段名，权限在SQL生成阶段注入
  3. 可审计性：查询计划是结构化的，便于审计和分析

查询计划格式示例：

{
  "metrics": [
    {
      "name": "gmv",
      "aggregation": "sum",
      "field": "order_amount",
      "filter": {"pay_status": "PAID"}
    }
  ],
  "dimensions": [
    {"name": "region", "value": "east_china"}
  ],
  "time_range": {
    "field": "pay_time",
    "start": "2025-04-01",
    "end": "2025-04-30"
  },
  "operations": [
    {"type": "group_by", "field": "category"},
    {"type": "order_by", "field": "gmv", "direction": "desc"}
  ]
}

7.5.4 语义层的持续演进

语义层不是一次性建设的，而是一个持续演进的活文档。

演进策略
策略说明频率
指标新增新业务产生新指标，及时纳入语义层按需
同义词扩展从用户查询日志中提取未覆盖的别名每周
口径变更指标口径变更时更新版本按需
未匹配分析分析用户查询未匹配的术语每日
质量评估评估语义层的覆盖率和准确率每月

💡 实践洞察： 语义层的质量直接决定了智能问数系统的查询准确率。建议设立专门的"语义层维护"角色，负责持续优化指标字典、同义词库和业务词典。

7.5.5 本章小结

指标语义层包含指标字典、维度字典、同义词库和业务词典四大核心组件，是将业务语言翻译为数据语言的桥梁。Text-to-SQL安全机制遵循"语义层生成查询计划 → SQL校验器检查 → 再执行"的三层防护架构，校验维度包括表权限、字段权限、扫描量、聚合逻辑、时间范围、敏感字段等。查询计划是结构化的查询描述，确保口径一致性和安全性。语义层需要持续演进，建议设立专门的维护角色。
