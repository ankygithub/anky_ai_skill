9.5 工具调用规范与记忆体系

Agent的核心能力之一是调用外部工具执行操作。本节定义工具调用的标准化规范，并深入阐述记忆管理的三个层次。

9.5.1 工具调用标准化规范

工具调用是Agent从"说"到"做"的桥梁。一个规范化的工具调用体系是Agent系统可靠运行的前提。 工具Schema定义

每个工具必须提供标准化的Schema定义，包括名称、描述、参数类型、必填项和返回值：

{
  "tool_name": "contract_query",
  "description": "从合同管理系统中查询合同信息",
  "parameters": {
    "type": "object",
    "properties": {
      "contract_id": {
        "type": "string",
        "description": "合同编号"
      },
      "party_name": {
        "type": "string",
        "description": "合同当事方名称（模糊匹配）"
      },
      "status": {
        "type": "string",
        "enum": ["draft", "active", "expired", "terminated"],
        "description": "合同状态"
      }
    },
    "required": ["contract_id"]
  },
  "return_type": {
    "type": "object",
    "properties": {
      "contract": { "type": "object" },
      "status": { "type": "string" }
    }
  }
}
参数校验规则

工具调用前必须对参数进行严格校验：

校验维度说明示例
类型校验参数类型必须匹配contract_id必须是字符串
必填校验必填参数不能缺失contract_id是必填项
枚举校验枚举值必须在允许范围内status只能是4种状态之一
格式校验参数格式必须正确日期格式为YYYY-MM-DD
业务校验参数必须符合业务规则合同编号必须符合编号规则
权限校验规则

工具调用必须进行权限校验，确保Agent有权限执行该操作：

校验维度说明
Agent权限Agent是否被授权调用此工具
数据权限Agent是否有权限访问该工具对应的数据
操作权限Agent是否有权限执行该工具对应的操作
上下文权限当前场景是否允许调用此工具
幂等Key机制

对于写操作工具，必须支持幂等Key，防止重复调用导致的数据不一致：

class IdempotentTool:
    """支持幂等性的工具调用"""
    
    def execute(self, tool_name: str, params: dict, idempotency_key: str = None):
        """执行工具调用，支持幂等性"""
        if not idempotency_key:
            idempotency_key = self.generate_idempotency_key(tool_name, params)
        
        # 检查是否已执行过
        existing = self.idempotency_store.get(idempotency_key)
        if existing:
            return existing  # 直接返回之前的结果
        
        # 执行工具调用
        result = self.call_tool(tool_name, params)
        
        # 记录幂等Key
        self.idempotency_store.set(idempotency_key, result, ttl=3600)
        
        return result
超时与重试

工具调用必须设置超时和重试机制：

配置项说明推荐值
超时时间工具调用的最大等待时间读操作：5秒；写操作：10秒
重试次数失败后的最大重试次数最多3次
重试间隔重试之间的等待时间指数退避：1s、2s、4s
熔断阈值连续失败次数触发熔断连续5次失败
错误码规范

工具调用的错误码必须标准化，便于Agent理解和处理：

错误码说明处理建议
TOOL_NOT_FOUND工具不存在检查工具注册，反馈给管理员
PARAM_VALIDATION_ERROR参数校验失败修正参数后重试
PERMISSION_DENIED权限不足向用户说明权限不足，请求人工介入
TIMEOUT调用超时重试，连续超时则标记工具不可用
RATE_LIMIT_EXCEEDED频率限制等待后重试
INTERNAL_ERROR工具内部错误重试，连续失败则触发熔断

9.5.2 工具分级管理

工具按风险等级分为两级，采用不同的安全策略：

✅ 只读工具（低风险）
- 知识检索 - 数据查询 - 文档分析 - 状态查询 **安全策略：** - 无需人工确认 - 自动执行 - 结果日志记录
⚠️ 写操作工具（高风险）
- 数据修改 - 审批提交 - 邮件发送 - 支付操作 **安全策略：** - 必须人工确认 - 操作前展示影响范围 - 操作后确认执行结果 - 完整审计日志
工具分级配置 
tool_risk_classification:

    - "status_check"
    permission_model: "auto_execute"
    audit_level: "log_only"
  
  high_risk:
    - "data_modify"
    - "approval_submit"
    - "email_send"
    - "payment_execute"

    audit_level: "full_audit"

9.5.3 记忆管理三层次

记忆管理是Agent从"一次性工具"进化为"持续进化的助手"的核心。记忆分为三个层次：短期上下文、长期向量记忆和脉络记忆。 第一层：短期上下文（Short-term Context）

短期上下文是Agent当前对话的上下文信息。

特性说明
存储方式对话历史列表
容量限制最大轮数（如20轮）或最大Token数（如4000）
生命周期单次会话，会话结束后自动清除
适用场景多轮对话的上下文维持
第二层：长期向量记忆（Long-term Vector Memory）

长期向量记忆是Agent历史交互的语义存储。

特性说明
存储方式向量数据库（Milvus/Chroma/FAISS）
检索方式语义相似度检索
容量限制理论上无限（取决于向量数据库容量）
生命周期永久存储，支持更新和删除
适用场景历史经验检索、相似案例匹配
 
class LongTermMemory:
    """长期向量记忆"""
    
    def __init__(self, vector_store, embedding_model):
        self.vector_store = vector_store
        self.embedding_model = embedding_model
    
    def store(self, interaction: dict):
        """存储交互记录"""
        # 将交互内容转化为向量
        content = f"{interaction['user_input']} → {interaction['agent_response']}"
        embedding = self.embedding_model.encode(content)
        
        # 存储到向量数据库
        self.vector_store.add(
            embedding=embedding,
            metadata={
                "user_id": interaction["user_id"],
                "timestamp": interaction["timestamp"],
                "task_type": interaction["task_type"],
                "result": interaction["result"]
            }
        )
    
    def retrieve(self, query: str, user_id: str = None, top_k: int = 5) -> list:
        """检索相关记忆"""
        query_embedding = self.embedding_model.encode(query)
        
        filters = {}
        if user_id:
            filters["user_id"] = user_id
        
        results = self.vector_store.search(
            query_embedding=query_embedding,
            top_k=top_k,
            filters=filters
        )
        
        return results
第三层：脉络记忆（Contextual Memory）

脉络记忆是跨会话学习的核心机制，它使得Agent能够从历史交互中学习用户偏好和行为模式。

特性说明
存储方式结构化记忆数据库（Memobase/A-MEM）
学习内容用户偏好、修正模式、常用操作、决策风格
更新方式自动学习 + 人工标注
生命周期长期存储，支持增量更新
适用场景个性化服务、持续优化
脉络记忆学习示例 
class ContextualMemory:
    """脉络记忆：跨会话学习"""
    
    def learn_from_correction(self, user_id: str, original_output: str, 
                               corrected_output: str, context: dict):
        """从人工修正中学习"""
        # 记录修正模式
        correction = CorrectionRecord(
            user_id=user_id,
            original_output=original_output,
            corrected_output=corrected_output,
            context=context,
            timestamp=datetime.now()
        )
        
        # 存储到脉络记忆
        self.memory_store.add_correction(correction)
        
        # 更新用户偏好
        self._update_user_preference(user_id, correction)
    
    def get_preference(self, user_id: str, category: str) -> Optional[str]:
        """获取用户偏好"""
        preferences = self.memory_store.get_user_preferences(user_id)
        return preferences.get(category)
    
    def apply_preferences(self, output: str, user_id: str, context: dict) -> str:
        """根据用户偏好调整输出"""
        preference = self.get_preference(user_id, context["task_type"])
        if preference:
            return self.adjust_output(output, preference)
        return output

9.5.4 记忆系统的融合使用

三个层次的记忆在Agent运行过程中协同工作：

用户输入
  ↓
感知层：收集场景上下文
  ↓
短期上下文：检查当前对话历史
  ↓
长期向量记忆：检索相似历史交互
  ↓
脉络记忆：获取用户偏好和修正模式
  ↓
综合以上信息，生成Agent回复
  ↓
执行操作（如需要）
  ↓
将交互结果存储到三层记忆中

9.5.5 本章小结

工具调用必须遵循标准化规范，包括Schema定义、参数校验、权限校验、幂等Key、超时重试和错误码解释。工具按风险等级分为只读（低风险，无需确认）和写操作（高风险，需人工确认）两级。记忆管理分为短期上下文（单次会话）、长期向量记忆（语义检索）和脉络记忆（跨会话学习）三个层次。三层记忆协同工作，使得Agent能够从历史交互中持续学习和优化。
