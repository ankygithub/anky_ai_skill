9.6 MCP协议：AI Agent的"USB标准"

MCP（Model Context Protocol）是2025年Anthropic提出的一个开放协议，旨在为大模型与外部工具、数据源之间提供标准化的交互方式。MCP被业界称为"AI Agent的USB标准"——就像USB标准统一了外设与计算机的连接方式，MCP统一了工具与大模型的连接方式。

9.6.1 MCP的核心价值

在MCP出现之前，每个Agent框架都有自己的工具调用规范：

  • LangChain有自己的Tool定义方式
  • OpenAI有自己的Function Calling格式
  • 每个Agent平台都有自己的插件接口

这导致工具开发者需要为每个框架分别实现适配层，大模型开发者也需要为每个工具格式编写解析器。MCP的价值在于提供一个统一的协议层：

维度MCP出现前MCP出现后
工具开发需要为每个框架开发适配层一次开发，通用所有支持MCP的Agent
模型集成需要为每个工具格式编写解析器统一通过MCP协议调用
生态发展碎片化，工具分散在不同平台标准化，形成统一的工具生态
维护成本每次框架更新都需要适配协议稳定，向后兼容

9.6.2 MCP协议核心概念

MCP协议定义了三个核心角色和一套标准化的消息格式：

三个角色
角色说明示例
Client（客户端）发起工具调用请求的一方Agent、大模型
Server（服务端）提供工具和数据服务的一方数据库连接器、API网关、文件系统
Host（宿主）协调Client和Server的中介MCP SDK、Agent平台
四类消息
消息类型方向说明
initializeClient → Server初始化连接，协商协议版本和能力
tools/listClient → Server查询Server提供的工具列表
tools/callClient → Server调用指定工具，传入参数
resources/readClient → Server读取Server提供的数据资源

9.6.4 MCP工具注册与发现

MCP Server实现（Python示例） 
from mcp.server import Server, NotificationOptions
from mcp.server.models import InitializationOptions
from mcp.types import Tool, TextContent

app = Server("contract-tools-server")

@app.list_tools()
async def list_tools() -> list[Tool]:
    """返回Server提供的工具列表"""
    return [
        Tool(
            name="contract_query",
            description="查询合同管理系统中的合同信息",
            inputSchema={
                "type": "object",
                "properties": {
                    "contract_id": {
                        "type": "string",
                        "description": "合同编号"
                    },
                    "party_name": {
                        "type": "string",
                        "description": "当事方名称（模糊匹配）"
                    }
                },
                "required": ["contract_id"]
            }
        ),
        Tool(
            name="regulation_search",
            description="搜索相关法规条款",
            inputSchema={
                "type": "object",
                "properties": {
                    "keyword": {
                        "type": "string",
                        "description": "搜索关键词"
                    },
                    "category": {
                        "type": "string",
                        "enum": ["civil", "commercial", "labor"],
                        "description": "法规类别"
                    }
                },
                "required": ["keyword"]
            }
        )
    ]

@app.call_tool()
async def call_tool(name: str, arguments: dict) -> list[TextContent]:
    """执行工具调用"""
    if name == "contract_query":
        contract_id = arguments.get("contract_id")
        party_name = arguments.get("party_name")
        
        # 查询合同管理系统
        contract = await query_contract_system(contract_id, party_name)
        
        if contract:
            return [TextContent(type="text", text=json.dumps(contract, ensure_ascii=False))]
        else:
            return [TextContent(type="text", text="未找到匹配的合同")]
    
    elif name == "regulation_search":
        keyword = arguments.get("keyword")
        category = arguments.get("category")
        
        # 搜索法规库
        regulations = await search_regulation_db(keyword, category)
        
        return [TextContent(type="text", text=json.dumps(regulations, ensure_ascii=False))]
    
    else:
        raise ValueError(f"未知工具: {name}")

9.6.5 MCP调用链路追踪

生产环境的MCP调用需要完整的链路追踪：

class MCPTracingMiddleware:
    """MCP调用链路追踪中间件"""
    
    async def intercept_call(self, request: ToolCallRequest, next_fn):
        """拦截工具调用，记录追踪信息"""
        trace_id = self.generate_trace_id()
        start_time = datetime.now()
        
        # 记录调用开始
        self.tracing_log.record({
            "trace_id": trace_id,
            "tool_name": request.tool_name,
            "arguments": self.sanitize_arguments(request.arguments),
            "start_time": start_time,
            "caller": request.caller_id,
            "status": "started"
        })
        
        try:
            # 执行调用
            result = await next_fn(request)
            
            # 记录调用成功
            elapsed = (datetime.now() - start_time).total_seconds() * 1000
            self.tracing_log.record({
                "trace_id": trace_id,
                "tool_name": request.tool_name,
                "status": "success",
                "elapsed_ms": elapsed,
                "result_size": len(json.dumps(result))
            })
            
            return result
            
        except Exception as e:
            # 记录调用失败
            elapsed = (datetime.now() - start_time).total_seconds() * 1000
            self.tracing_log.record({
                "trace_id": trace_id,
                "tool_name": request.tool_name,
                "status": "error",
                "error_type": type(e).__name__,
                "error_message": str(e),
                "elapsed_ms": elapsed
            })
            raise

9.6.6 MCP超时重试与降级

class MCPRetryHandler:
    """MCP调用重试与降级处理器"""
    
    def __init__(self, max_retries=3, timeout_seconds=10):
        self.max_retries = max_retries
        self.timeout_seconds = timeout_seconds
        self.circuit_breakers = {}  # 每个工具的熔断器
    
    async def call_with_retry(self, tool_name: str, arguments: dict) -> dict:
        """带重试和熔断的工具调用"""
        # 检查熔断状态
        if self.is_circuit_open(tool_name):
            raise CircuitBreakerOpenError(f"工具 {tool_name} 熔断器已打开")
        
        last_error = None
        for attempt in range(self.max_retries):
            try:
                result = await self.call_tool_with_timeout(
                    tool_name, arguments, self.timeout_seconds
                )
                # 调用成功，重置熔断器
                self.reset_circuit_breaker(tool_name)
                return result
                
            except TimeoutError as e:
                last_error = e
                wait_time = 2 ** attempt  # 指数退避
                await asyncio.sleep(wait_time)
                
            except Exception as e:
                last_error = e
                # 非超时错误，检查是否需要熔断
                if self.should_open_circuit(tool_name):
                    self.open_circuit_breaker(tool_name)
                    raise
        
        # 所有重试失败
        if last_error:
            self.record_failure(tool_name)
            if self.should_open_circuit(tool_name):
                self.open_circuit_breaker(tool_name)
            raise last_error
    
    async def call_tool_with_timeout(self, tool_name: str, arguments: dict, timeout: float):
        """带超时的工具调用"""
        try:
            return await asyncio.wait_for(
                self.mcp_client.call_tool(tool_name, arguments),
                timeout=timeout
            )
        except asyncio.TimeoutError:
            raise TimeoutError(f"工具调用超时: {tool_name}, 超时时间: {timeout}秒")

9.6.7 Agent工作流配置示例（YAML）

# agent-workflow.yaml
# Agent工作流配置，集成MCP工具调用

agent:
  name: "contract_review_agent"
  model: "qwen-max-latest"
  
  mcp_servers:
    - name: "contract-system"
      url: "http://contract-tools-server:8080/mcp"
      tools: ["contract_query", "contract_history"]
    
    - name: "regulation-db"
      url: "http://regulation-server:8080/mcp"
      tools: ["regulation_search", "case_search"]

  workflow:
    steps:
      - step: 1
        action: "mcp_call"
        server: "contract-system"
        tool: "contract_query"
        arguments:
          contract_id: "{{user_input.contract_id}}"
        output: "contract_data"
      
      - step: 2
        action: "llm_analyze"
        prompt: "请分析以下合同的风险条款：{{contract_data}}"
        output: "risk_analysis"
      
      - step: 3
        action: "mcp_call"
        server: "regulation-db"
        tool: "regulation_search"
        arguments:
          keyword: "{{risk_analysis.top_risk_keywords}}"
          category: "commercial"
        output: "regulations"
      
      - step: 4
        action: "llm_synthesize"
        prompt: |
          基于以下信息生成合同审查报告：
          - 合同数据：{{contract_data}}
          - 风险分析：{{risk_analysis}}
          - 相关法规：{{regulations}}
        output: "review_report"
      
      - step: 5
        action: "human_review"
        condition: "risk_analysis.has_critical_risk"
        output: "final_report"

9.6.8 本章小结

MCP（Model Context Protocol）是大模型与外部工具、数据源之间标准化交互的开放协议，被誉为"AI Agent的USB标准"。MCP定义了Client、Server、Host三个角色和initialize、tools/list、tools/call、resources/read四类消息。工具注册通过MCP Server实现，调用链路需要完整的追踪机制，超时重试采用指数退避和熔断器模式。企业应优先选择支持MCP协议的工具和平台，以获得最大的生态兼容性和最低的集成成本。
