第四章 核心组件详解

从"知道用什么"到"理解怎么选、怎么配、怎么调优"

4.1 接入层组件

接入层 是AI系统与外部世界的边界，负责流量管理、安全控制和协议转换。在AI系统中，接入层的设计直接影响系统的可用性、安全性和性能。

4.1.1 API网关

方案类型特点适用场景
Kong开源/商业基于Nginx，插件生态丰富，支持Rate Limiting、JWT认证、请求转换中大型企业，需要丰富插件生态
Nginx开源高性能反向代理，配置灵活，社区成熟简单场景，或作为Kong的底层引擎
APISIX开源国产网关，动态配置热加载，性能优异，适合云原生中国团队，云原生架构
Envoy开源云原生服务代理，支持gRPC、HTTP/2、高级负载均衡微服务架构、Service Mesh
AI系统的特殊需求：
  • 流式响应支持：LLM的SSE（Server-Sent Events）流式输出需要网关正确透传，不能缓存或截断
  • 长超时配置：某些Agent任务可能运行数分钟，需要配置足够长的超时时间
  • 大请求体支持：多模态输入（图片+文本）可能产生较大的请求体
Kong配置示例（AI流式响应透传）： 
# Kong Service 配置
service:
  name: ai-model-service
  url: http://model-server:8000
  connect_timeout: 60000    # 连接超时 60s
  write_timeout: 300000     # 写入超时 5分钟
  read_timeout: 300000      # 读取超时 5分钟

# 禁止响应缓存
plugins:
  - name: response-transformer
    config:
      remove:
        headers:
          - Cache-Control
          - X-Accel-Buffering

4.2 编排层组件

编排层 是AI系统的"大脑"，负责任务规划、工具调用和Agent流程控制。

4.2.1 Agent编排模式

模式一：ReAct（Reasoning + Acting）

ReAct是最经典的Agent编排模式，核心思想是让模型在"推理"和"行动"之间交替进行：

Thought: 用户想知道今天的销售数据
Action: 调用 sales_api(query="today")
Observation: 返回 {total: 1250000, orders: 342}
Thought: 数据已获取，需要汇总并格式化
Answer: 今日销售额125万元，共342笔订单...
适用场景： 需要多步骤推理和工具调用的任务，如数据查询、信息检索、问题排查。 模式二：Plan-and-Execute

先让模型制定完整计划，再按计划逐步执行：

Plan:
  1. 查询用户历史订单
  2. 分析用户偏好
  3. 检索当前促销商品
  4. 生成个性化推荐列表
  
Execute Step 1 → 结果 → Execute Step 2 → ...
适用场景： 需要多步骤、可预测流程的复杂任务，如报告生成、数据分析。 模式三：工具调用（Tool Calling / Function Calling）

模型直接输出结构化的工具调用请求，由系统执行后返回结果：

{
  "tool_calls": [
    {
      "name": "query_database",
      "arguments": {
        "sql": "SELECT * FROM orders WHERE date = '2026-01-15'"
      }
    }
  ]
}
适用场景： 需要精确调用外部API的场景，如数据库查询、业务系统操作。

模型选择不是"选最强的"，而是"选最合适的"。2026年的务实策略是建立模型分级体系：简单任务用小模型，复杂任务用大模型，关键任务用多模型协作。

4.3.2 模型路由设计

用户请求
    │
    ▼
┌─────────────┐
│ 意图分类器   │  ← 判断任务复杂度（L1-L4）
└──────┬──────┘
       │
  ┌────┼────┬────┐
  ▼    ▼    ▼    ▼
 L1   L2   L3   L4
小模型 中模型 大模型 多模型
DeepSeek Qwen  GPT-4o +人工审核
V4-Pro  -7B   Claude 4
路由策略规则示例： 
routing_rules:
  - condition: task_type IN ["classification", "extraction", "formatting"]
    model: deepseek-v4-pro
    reason: "简单任务，小模型足够"
  
  - condition: task_type == "rag_qa" AND doc_count < 10
    model: qwen-7b
    reason: "中等任务，本地模型即可"
  
  - condition: task_type == "complex_reasoning" OR user_tier == "premium"
    model: gpt-4o
    reason: "复杂推理或VIP用户"
  
  - condition: risk_level == "critical"
    strategy: multi_model_vote
    models: [gpt-4o, claude-4, qwen-max]
    reason: "关键任务需要多模型交叉验证"

4.3.3 Prompt管理

Prompt管理 是AI系统工程化的重要基础，核心要求是：可版本化、可测试、可回滚。 最佳实践：
  1. 模板化：将Prompt参数化，通过模板引擎（Jinja2、Mustache）渲染
  2. 版本化：每个Prompt模板有明确的版本号，记录变更历史
  3. A/B测试：同时运行多个版本的Prompt，对比效果
  4. 自动化评估：使用LLM-as-a-Judge或RAGAS自动评估Prompt效果
  5. 回滚机制：新Prompt效果不佳时能快速回滚到上一版本

4.5.2 LLM-as-a-Judge

LLM-as-a-Judge 是用一个更强的LLM来评估其他模型的输出质量。这是2026年最主流的AI质量评估方法。 基本流程： 
1. 准备测试集（问题 + 标准答案）
2. 待评估模型生成回答
3. Judge模型根据评分标准打分
4. 统计分析各项指标
Judge Prompt 示例： 
你是一个专业的AI回答质量评估员。请根据以下标准评估AI回答的质量：

问题：{question}
标准答案：{reference_answer}
AI回答：{model_response}

评估维度：
1. 准确性（0-5）：回答是否正确、无事实错误
2. 完整性（0-5）：是否覆盖了问题的所有方面
3. 相关性（0-5）：是否直接回答问题
4. 可读性（0-5）：语言是否流畅、易懂

请逐项给出评分和简短理由。

4.5.3 可观测性

三大支柱：
支柱内容工具
日志（Logging）结构化记录每次请求的输入输出、Token消耗、模型选择ELK、Loki
指标（Metrics）延迟、吞吐、错误率、成本、用户满意度Prometheus、Grafana
追踪（Tracing）完整记录请求在各层之间的执行路径和耗时OpenTelemetry、LangSmith

可观测性是AI系统从Demo走向生产的必备能力。没有可观测性的AI系统就像"蒙眼开车"——出了问题不知道原因，更无法持续优化。

4.6 本章小结

本章逐层详解了AI系统的核心组件和技术选型：

层级关键组件选型要点
接入层Kong/Nginx/Sentinel流式透传、长超时、限流熔断
编排层ReAct/Plan-and-Execute/工具调用按任务复杂度选择编排模式
模型层GPT-4o/Claude/Qwen/DeepSeek分级使用，不盲目追求大模型
数据层Milvus/Qdrant/Neo4j按数据规模和查询需求选择
运维层RAGAS/TruLens/LLM-as-a-Judge质量评估是可观测性的核心

每个组件的选择都需要权衡功能、性能、成本和团队能力。下一章将深入对比AI系统与传统系统的本质差异，帮助架构师做出正确的架构决策。
