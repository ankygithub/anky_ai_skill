第11.7章 金融AI——技术选型与示例代码

11.7.1 金融AI技术栈全景

金融AI系统的技术栈横跨多个技术领域，涵盖传统机器学习、深度学习、大模型、实时计算和特征工程。技术选型的核心原则是"可解释性优先、实时性保障、合规性兜底"。

金融AI技术栈按功能分层：
层级技术组件代表产品/框架金融场景
模型层时序异常检测LSTM/AutoEncoder/Isolation Forest交易欺诈检测
模型层图神经网络GraphSAGE/GAT/Neo4j GDS关联交易挖掘
模型层大模型解释金融垂类LLM + RAG审批摘要/合规审查
计算层实时计算Apache Flink/Kafka Streams毫秒级风控拦截
特征层特征平台Tecton/Feast/自研特征仓特征复用与版本管理
可解释层SHAP/LIMEshap库/ELI5/自研解释引擎模型输出归因

11.7.2 模型选型策略

金融场景的模型选型需要平衡准确性、可解释性和实时性三个维度：

XGBoost + 大模型融合架构是行业主流方案： 
┌─────────────────────────────────────────────┐
│              大模型层（解释与生成）             │
│  材料解析 / 风险摘要 / 审批建议 / 合规审查      │
│  优势：语义理解强、生成能力强                   │
│  劣势：推理延迟高、可解释性弱                   │
├─────────────────────────────────────────────┤
│              XGBoost层（风控评分）              │
│  信用评分 / 欺诈检测 / 违约预测                 │
│  优势：可解释性强（SHAP值）、推理快、效果稳定   │
│  劣势：仅处理结构化特征                       │
├─────────────────────────────────────────────┤
│              特征层                           │
│  结构化特征（交易/资产/征信）+ 非结构化特征     │
│  （文本embedding/图像OCR结果）                 │
└─────────────────────────────────────────────┘
选型决策矩阵：
场景推荐模型理由
信用评分卡XGBoost/逻辑回归可解释性强，满足监管要求
关联交易识别图神经网络（GraphSAGE）天然适合关系网络分析
材料解析/摘要金融垂类大模型 + RAG语义理解与生成能力强
实时交易风控XGBoost + 规则引擎毫秒级延迟要求
合规文案审查大模型 + 规则引擎语义理解 + 确定性规则

11.7.3 示例代码：风险评分接口

以下是基于XGBoost的风险评分服务接口示例：

from fastapi import FastAPI
from pydantic import BaseModel
import xgboost as xgb
import shap
import numpy as np

app = FastAPI(title="金融风险评分服务")

# 加载预训练模型
model = xgb.Booster()
model.load_model("models/credit_risk_v2.json")

class RiskScoreRequest(BaseModel):
    applicant_id: str
    features: dict  # 结构化特征：年龄/收入/DTI/征信分/历史逾期等

@app.post("/api/v1/risk-score")
async def risk_score(req: RiskScoreRequest):
    """风险评分接口"""
    # 1. 特征向量化
    feature_vector = vectorize_features(req.features)
    dmatrix = xgb.DMatrix(feature_vector)
    
    # 2. 模型推理
    pred_prob = model.predict(dmatrix)[0]
    risk_score = int(pred_prob * 1000)  # 0-1000分制
    
    # 3. SHAP可解释性分析
    explainer = shap.TreeExplainer(model)
    shap_values = explainer.shap_values(feature_vector)
    top_features = get_top_contributing_features(
        feature_vector, shap_values, top_k=5
    )
    
    # 4. 风险等级判定
    risk_level = classify_risk(risk_score)
    
    return {
        "applicant_id": req.applicant_id,
        "risk_score": risk_score,
        "risk_level": risk_level,
        "default_probability": round(pred_prob, 4),
        "top_factors": top_features,
        "model_version": "credit_risk_v2",
        "timestamp": get_current_timestamp()
    }

11.7.6 特征平台选型对比

维度TectonFeast自研特征仓
定位商业化特征平台开源特征存储定制化开发
实时特征原生支持需自建需自建
特征版本管理完善基础需开发
在线/离线一致性自动保障需手动维护需开发
金融行业案例丰富中等取决于自研能力
成本较高低中等（人力成本）
推荐场景大型金融机构中小型机构/POC阶段有强定制需求

[!TIP] 特征工程最佳实践

金融场景的特征工程应遵循"一次定义、多处复用"原则。使用特征平台统一管理特征定义，确保训练环境和推理环境的特征计算逻辑一致，避免训练-推理偏差（Training-Serving Skew）。
