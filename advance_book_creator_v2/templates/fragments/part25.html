第二十五章 企业知识库——文档处理与权限控制

从"读得懂"到"看得见"——文档解析与安全边界的实战指南

5.8.1 8种核心文档类型及处理难点

企业知识库中的文档类型千差万别，每种类型都有其独特的解析难点。以下是8种必须重点处理的文档类型：

类型一：制度文档

制度文档是企业中最常见的知识类型，包含公司制度、流程规范、管理办法等。
特征难点处理策略
结构清晰（章节/条款/条目）条款之间有层级关系，切片时需要保持层级按章节切分，保留标题层级元数据
语言正式、精确术语密集，需要准确理解使用领域增强Embedding模型
频繁更新新旧版本容易混淆严格版本管理，旧版本降权

类型二：产品手册

特征难点处理策略
产品参数、规格密集参数表格需要完整保留表格结构识别（TSR）+ 独立切片
多版本产品不同版本参数不同版本标签+产品型号元数据
图文混排图片中的信息也需要理解OCR+图片描述生成

类型三：技术文档

特征难点处理策略
代码片段、API文档代码与普通文本混合代码块独立识别+语法高亮标记
大量专业术语Embedding模型可能不覆盖术语表注入+领域微调
版本强关联不同软件版本对应不同文档Git版本号+文档版本绑定

类型四：表格文档（Excel）

表格文档是企业中最难处理的知识类型之一。
特征难点处理策略
数据密集、结构复杂行列关系、合并单元格、多层表头表格结构解析→行转文本→语义标注
公式计算单元格内容是公式结果提取计算结果值+公式说明
多Sheet不同sheet之间可能有关联每个sheet独立切片，关联元数据
表格切片示例： 
原始表格：
| 职级 | 基本工资 | 绩效比例 | 年休假天数 |
|------|---------|---------|-----------|
| P5   | 15000   | 20%     | 10        |
| P6   | 20000   | 25%     | 12        |

切片后（每行一个切片）：
切片1: "职级P5: 基本工资15000元，绩效比例20%，年休假10天"
切片2: "职级P6: 基本工资20000元，绩效比例25%，年休假12天"

类型五：PPT演示文稿

特征难点处理策略
幻灯片式排版每页内容独立但上下文关联逐页解析+演讲者备注提取
图文混排图表信息在图片中图表OCR+图片描述
精简表达文字少、信息密度高结合演讲者备注补全语义

类型六：图片扫描件

特征难点处理策略
无文本层必须依赖OCR高质量OCR引擎+版面分析
表格/印章印章覆盖文字影响识别印章去除算法+表格恢复
手写内容OCR准确率大幅下降标记为"待人工校对"

类型七：聊天记录（企微/飞书/钉钉）

特征难点处理策略
碎片化一条信息可能只有几个字时间窗口聚合+话题聚类
口语化非正式表达，包含缩写和表情口语→书面语转换
上下文依赖单条信息无意义，需要上下文会话上下文保留

类型八：工单记录

特征难点处理策略
问答结构问题-解答成对出现提取问答对作为独立知识
解决方案沉淀优秀的解决方案需要提炼LLM自动提炼+人工审核
时效性强某些问题只在特定时期出现时效标签+定期清理

5.8.2 权限控制核心原则

权限控制是企业知识库的安全底线。RAG系统的权限控制有一个绝对不能违反的核心原则：

🚫 RAG不能先把无权限内容召回再交给大模型过滤

这个原则的原因是：

风险说明
数据泄露即使大模型被Prompt要求"不要展示无权限内容"，但无权限内容已经被送入模型上下文，存在泄露风险
Prompt注入恶意用户可能通过特殊提问绕过Prompt中的权限过滤指令
审计困难无权限内容被送入模型但被过滤，这种"隐形泄露"无法审计
合规风险违反《数据安全法》和《个人信息保护法》中的"最小必要"原则
正确的权限控制方式：检索前或检索时做权限裁剪 
✅ 正确做法：
用户查询 ──→ 获取用户权限列表 ──→ 在检索时过滤无权限文档 ──→ 只返回有权限的结果

❌ 错误做法：
用户查询 ──→ 检索所有文档（含无权限） ──→ 大模型根据权限过滤 ──→ 返回结果

5.8.3 ACL元数据设计

ACL（Access Control List，访问控制列表）元数据是权限控制的数据基础。每个知识切片在入库时都需要关联权限元数据。 ACL元数据字段设计：
字段类型说明示例
doc_idstring文档唯一标识"DOC-HR-2026-001"
sourcestring数据来源"飞书-HR制度空间"
permissionslist[string]允许访问的角色/部门/用户["all_staff", "hr_dept"]
deny_listlist[string]明确禁止访问的用户["user_001", "user_002"]
security_levelstring安全等级"public"/"internal"/"confidential"/"secret"
ownerstring文档责任人"hr_admin"
created_attimestamp创建时间"2026-01-15T10:30:00Z"
expires_attimestamp过期时间（可选）"2026-12-31T23:59:59Z"
权限过滤伪代码： 
def build_permission_filter(user_id: str) -> dict:
    """构建权限过滤条件"""
    # 获取用户所属角色和部门
    user_roles = get_user_roles(user_id)    # ["all_staff", "tech_dept"]
    user_dept = get_user_department(user_id) # "tech_dept"
    
    # 构建Milvus/ES过滤条件
    filter_expr = {
        "$or": [
            {"permissions": {"$in": user_roles}},  # 角色匹配
            {"permissions": {"$in": [user_dept]}},  # 部门匹配
            {"security_level": "public"}             # 公开文档
        ],
        "$and": [
            {"deny_list": {"$nin": [user_id]}}       # 不在拒绝列表中
        ]
    }
    return filter_expr

# 检索时应用权限过滤
def search_with_permission(query_vector, user_id):
    filter_expr = build_permission_filter(user_id)
    results = vector_db.search(
        vector=query_vector,
        filter=filter_expr,  # 检索时即过滤
        top_k=20
    )
    return results
⚠️ 权限同步延迟问题

当用户权限发生变化时（如调岗、离职），需要确保知识库的权限过滤立即生效。建议：

  • 权限变更事件通过消息队列实时通知知识库系统
  • 知识库系统在收到权限变更通知后立即更新缓存
  • 对于特别敏感的权限变更（如离职），建议在检索时实时查询最新权限而非依赖缓存

5.8.4 答案溯源机制

答案溯源是指将AI生成的答案中的每一段内容，追溯到其来源文档的具体位置。这不仅是可信度保障，更是权限控制的延伸——如果答案的某个片段来自用户无权限的文档，则该片段不应展示。 溯源层级设计：
层级精度技术实现适用场景
文档级定位到文档文档ID+文档名基础场景
章节级定位到章节/段落文档ID+章节标题制度文档、手册
页码级定位到页码文档ID+页码PDF文档
句子级定位到具体句子文档ID+段落ID+句子偏移量高精度要求的场景
溯源与权限的联动： 
AI生成答案：
"根据《2026年员工手册》第12条，年假天数为..."
         ↓
检查用户权限：
- 《2026年员工手册》的权限要求：all_staff
- 当前用户角色：all_staff ✅ 有权限
         ↓
答案正常展示 + 标注来源

如果用户无权限：
- 该文档不在用户权限范围内 ❌
         ↓
答案中删除该片段，返回：
"关于年假天数的规定，您暂无权限查看。"

5.8.5 本章小结

文档处理是RAG管道的"前置关卡"，8种核心文档类型各有其解析难点，需要针对性的处理策略。其中，表格文档和扫描件是最具挑战的两类。权限控制是知识库的安全底线，核心原则是"检索前或检索时做权限裁剪"，绝不能在检索后交给大模型过滤。ACL元数据设计和答案溯源机制是权限控制的两个关键技术环节。没有严格的权限控制，知识库就不是"知识资产"而是"泄风险"。下一章将介绍技术选型与示例代码。
