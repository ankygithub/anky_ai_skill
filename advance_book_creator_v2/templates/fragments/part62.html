11.2 金融AI——智能风控系统

11.2.1 产品经理视角：功能需求拆解

智能风控是金融AI系统中最核心、最成熟的场景之一。作为产品经理，我们需要从"用户风险是什么"出发，逐层拆解系统功能。

核心用户故事：

作为风控审核员，我希望在用户提交申请后100ms内获得风险评估结果，包括用户画像摘要、风险评分、风险点解释和处置建议，以便我快速做出审批决策。

功能需求清单： FR-001：用户风险画像

系统需要构建多维度的用户风险画像，涵盖：

  • 身份信息：实名认证状态、职业、收入区间、教育程度
  • 交易行为：历史交易频次、交易金额分布、异常交易标记
  • 设备信息：设备指纹、常用设备数、设备更换频率、模拟器检测
  • 历史行为：历史申请记录、逾期记录、投诉记录、黑名单命中
FR-002：申请风险评估

基于用户画像和当前申请信息，输出：

  • 综合风险评分（0-100分，分数越高风险越高）
  • 风险等级（低/中/高/拒绝）
  • 各维度分项评分（身份风险、信用风险、行为风险、设备风险）
FR-003：反欺诈检测

实时检测以下异常模式：

  • 异常设备：模拟器、root/jailbreak设备、设备指纹异常
  • 异常IP：代理IP、数据中心IP、高风险地区IP、IP频繁切换
  • 批量注册：同一设备/IP短时间内多次申请、相似信息批量提交
  • 行为异常：非人类操作模式（如填写速度异常均匀）、深夜高频操作
FR-004：规则引擎

支持业务人员配置和调整风控规则：

  • 规则DSL：IF device_score > 80 AND ip_risk == 'high' THEN risk_level = 'reject'
  • 规则版本管理：每次规则变更保留版本快照，支持策略回溯
  • 规则-模型协同：规则优先（硬性拦截）→ 模型评分（弹性评估）→ 人工审核（灰度决策）
FR-005：风险解释

每个风险评分必须附带可解释性输出：

  • 评分依据："设备风险分85分，主要因为检测到模拟器环境"
  • 关键因子权重：SHAP值展示各特征对最终评分的贡献度
  • 原始数据引用：指向具体的设备指纹日志、IP归属地数据
FR-006：人工审核流转
  • 低风险（0-30分）：自动通过
  • 中风险（31-60分）：AI建议+人工快速确认
  • 高风险（61-80分）：人工详细审核
  • 拒绝（81-100分）：自动拒绝+可申诉通道
FR-007：风险监控看板
  • 实时流量监控：申请量、通过率、拒绝率、转人工率
  • 风险趋势：各风险等级的时间序列变化
  • 规则命中统计：各规则的触发频次和拦截效果
  • 模型性能漂移：模型KS值、AUC值的时间趋势

系统架构分层： 
┌─────────────────────────────────────────────────┐
│                  前端交互层                       │
│     审核工作台 · 规则配置台 · 监控看板            │
├─────────────────────────────────────────────────┤
│                  服务编排层                       │
│     风控API网关 · 流程编排 · 决策引擎             │
├─────────────────────────────────────────────────┤
│                  AI能力层                         │
│     特征工程服务 · 模型推理服务 · 规则引擎        │
├─────────────────────────────────────────────────┤
│                  数据层                           │
│     实时特征库 · 离线特征库 · 决策日志库          │
└─────────────────────────────────────────────────┘
关键技术选型：
层级技术选项选型理由
实时计算Flink / Kafka Streams毫秒级延迟、状态管理、Exactly-Once语义
特征存储Redis + Tecton / Feast低延迟读取、在线离线特征一致性
模型推理自研推理框架 / Triton支持多种模型格式、GPU加速
规则引擎Drools / 自研DSL业务人员可配置、版本管理
可解释性SHAP / LIME开源成熟、业界标准
100ms延迟保障策略：
  1. 特征预计算：用户画像类特征提前计算并缓存，实时仅需增量特征
  2. 模型轻量化：线上使用蒸馏后的小模型，推理延迟<20ms
  3. 规则前置：硬性拦截规则在特征获取阶段即执行，避免无效推理
  4. 并行计算：各维度特征提取和模型推理并行执行

11.2.5 本章小结

智能风控系统的核心挑战不在于模型本身的准确性，而在于在100ms延迟约束下完成多维度风险识别、可解释输出和审计留痕。产品经理需要理解风控的业务逻辑和验收标准，架构师需要在实时性、可解释性和可扩展性之间找到平衡点。
