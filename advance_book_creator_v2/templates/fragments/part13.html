4.6.2 意图识别

意图识别 是AI客服最核心的能力，决定了系统能否正确理解用户的需求。

技术方案对比

方案技术路径准确率延迟成本适用场景
BERT微调预训练BERT + 业务数据微调75-85%<50ms低意图数量 <200、对延迟敏感
大模型分类LLM Prompt分类（Zero-shot/Few-shot）80-90%200-500ms中意图数量多、需要灵活扩展
规则+模型混合规则兜底 + 模型判断80-88%<100ms低关键场景需要确定性保障
多模型投票BERT + LLM + 规则综合投票85-92%300-600ms高高准确率要求的场景

容联七陌实测数据

根据容联七陌 2026年发布的智能客服平台性能报告（获取时间：2026-03-20），其意图识别模块在电商场景的实测数据：

指标数值说明
意图识别准确率≥82%在Top 100意图上的平均准确率
Top 3 召回率≥95%正确意图在前3个候选中的比例
首Token延迟<200ms从用户输入到意图识别完成的时间
低置信度占比<15%置信度 <70% 的会话占比
意图数量50-300个按企业规模不同

实测经验：意图识别准确率在 <80% 时，用户体验明显下降；达到 82-85% 时，用户体验可接受；超过 90% 时，用户体验显著提升。因此，82% 是意图识别的"及格线"，85% 是"优秀线"。

意图识别优化策略

优化策略说明效果
增加训练数据每个意图至少20条训练语料，覆盖不同表达方式准确率 +3-5%
同义词扩展为每个意图维护同义词表，增强泛化能力准确率 +2-3%
上下文增强将前一轮对话内容作为意图识别的额外输入准确率 +2-4%
意图冲突检测定期检测意图之间的语义重叠，合并或拆分准确率 +1-2%
在线学习利用人工标注的低置信度会话持续更新模型准确率 +1-3%/月

4.6.3 实体抽取

实体抽取（Named Entity Recognition, NER） 从用户输入中提取关键业务信息，是意图识别的补充能力。

常见实体类型

实体类型示例抽取方式用途
订单号"ORD-20260523-001"正则表达式关联订单查询
手机号"138**5678"正则表达式身份验证
商品名称"iPhone 15 Pro"词典匹配 + NER模型关联商品咨询
时间"昨天""上周""2026年5月"时间解析模型限定查询范围
金额"2000元""两千块"金额解析模型退款/赔付判断
地址"北京市朝阳区..."NER模型地址修改
快递单号"SF1234567890"正则表达式物流查询

4.6.4 RAG问答引擎

RAG（Retrieval-Augmented Generation，检索增强生成） 是智能客服回答标准问题的核心技术。

RAG架构流程

用户问题
    │
    ▼
┌──────────────────┐
│  问题预处理       │ ← 去噪、分词、纠错、意图关联
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│  向量化（Embedding）│ ← 将问题转换为向量表示
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│  向量检索          │ ← 在知识库向量数据库中检索Top-K
│  (Milvus/ES)      │   相关文档片段
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│  结果重排序        │ ← 基于相关性、时效性、权威性重排序
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│  上下文组装        │ ← 将Top-3文档片段组装为Prompt上下文
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│  LLM生成答案      │ ← 基于上下文生成最终回答
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│  答案后处理        │ ← 格式校验、敏感词过滤、来源标注
└────────┬─────────┘
         │
         ▼
    返回给用户

RAG关键参数建议

参数建议值说明
检索Top-KK=5-10检索5-10个相关文档片段
重排序Top-NN=3重排序后取Top-3作为上下文
上下文窗口4000-8000 tokens根据模型上下文窗口调整
相似度阈值>0.75低于阈值认为无相关知识
分块大小500-1000 tokens知识库文档分块大小
分块重叠10-15%相邻分块的重叠比例

RAG效果优化策略

策略说明效果
混合检索向量检索 + BM25关键词检索召回率 +5-10%
文档预处理去除噪声、结构化提取关键信息准确率 +3-5%
元数据过滤按文档类型、有效期、版本过滤准确率 +2-3%
Prompt优化添加回答约束和格式要求回答质量显著提升

4.6.6 情绪识别

情绪识别 通过分析用户文本判断其情绪状态，是转人工和话术调整的重要依据。

情绪分类体系

情绪类别特征词处理策略
平静正常表达、无强烈情感词标准话术
焦虑"着急""快点""怎么还没"加快速度、安抚话术
不满"太差了""不满意""失望"安抚话术、快速解决
愤怒攻击性词汇、大量感叹号立即转人工(P0)
满意"谢谢""很好""满意"感谢话术、引导评价

情绪识别技术方案

方案技术路径准确率延迟
规则匹配情感词典 + 正则表达式60-70%<10ms
分类模型BERT微调（5分类）75-85%<50ms
LLM判断大模型Prompt判断80-90%200-500ms
混合方案规则快速判断 + 模型精细判断82-88%<100ms

建议方案：情绪识别推荐使用混合方案——规则引擎快速识别极端情绪（愤怒），模型精细判断一般情绪（焦虑/不满/平静），兼顾速度和准确率。

4.6.7 对话摘要

对话摘要 将长对话压缩为结构化摘要，便于人工客服快速了解上下文。

摘要模板

【会话摘要】
用户ID：U-20260523-0001
会话渠道：网页
会话时长：5分钟 / 8轮

【主要意图】
1. 订单查询（置信度89%）
2. 物流咨询（置信度85%）

【关键信息】
- 查询订单：ORD-20260522-1234
- 订单状态：仓库处理中，预计明天发货
- 用户关注点：发货时效

【处理结果】
- AI已解答发货时间
- 用户表示满意

【情绪变化】
平静 → 平静（无明显情绪波动）

【是否转人工】
否

摘要生成技术

方案说明优缺点
模板填充从对话中提取结构化信息填充模板速度快、可控性强，但灵活性差
LLM摘要使用LLM自动总结对话要点灵活度高，但成本和延迟较高
模板+LLM混合模板保证结构，LLM填充内容兼顾速度和质量

4.6.8 工单分类

工单分类 自动将工单分类到正确的处理组和优先级，是工单自动分派的前提。

分类维度

维度分类值分类依据
问题类型售前/售后/订单/账户/投诉会话意图识别结果
紧急程度P0/P1/P2/P3情绪识别 + 业务规则
技能组售前组/售后组/物流组/投诉组问题类型 + 业务归属
处理渠道AI自助/人工在线/人工电话问题复杂度 + 用户偏好

工单分类技术方案

工单分类本质上是一个多标签分类问题，可以使用以下方案：

方案适用场景准确率
规则分类问题类型明确、规则固定85-90%
文本分类模型需要从工单描述中自动分类78-85%
意图复用直接复用会话意图识别结果82-88%

4.6.9 质检分析

质检分析 通过AI自动评估AI客服和人工客服的服务质量。

AI质检维度

维度评估方法权重
回答准确性与标准答案比对、知识库命中率35%
服务态度情绪分析、礼貌用语检测20%
流程合规关键步骤是否执行（如确认机制）20%
响应速度首响时间、平均响应时间15%
解决效果用户满意度、问题解决率10%

质检分析技术方案

质检方式技术路径覆盖率准确度
规则质检基于业务规则自动检查100%高（规则明确时）
模型质检NLP模型评估回答质量100%中-高
LLM质检大模型综合评估100%高
人工抽检质检人员手动评分5-10%最高

最佳实践：AI质检覆盖100%的会话，用于初筛和趋势分析；人工抽检5-10%的重点会话，用于校准AI质检结果和深度分析。两者结合，既保证覆盖率又保证准确度。

4.6.10 本章小结

智能客服的八大核心AI能力模块（意图识别、实体抽取、RAG问答、多轮对话管理、情绪识别、对话摘要、工单分类、质检分析）共同构成了AI客服的"智能中枢"。每个模块都有多种技术方案可选，选型时应综合考虑准确率、延迟、成本和维护复杂度。下一章将介绍智能客服与业务系统的对接方案和高并发架构设计。
