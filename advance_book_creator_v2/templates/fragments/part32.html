第三十二章 AI编程助手——上下文收集与多Agent协作

6.5 上下文收集策略与多Agent协作机制

AI编程助手的核心竞争力不仅在于模型本身的编码能力，更在于"如何让模型理解当前的编码上下文"以及"如何组织多个AI Agent协同完成复杂任务"。本节深入解析上下文收集的技术方案和多Agent协作的运行机制。

6.5.1 上下文收集的必要性

大模型的上下文窗口虽然越来越大（从8K到128K甚至更大），但"能装多少"和"应该装什么"是两个完全不同的问题。如果将所有代码都塞入Prompt，会导致：

  • 延迟飙升：大量Token的推理耗时会显著增加
  • 注意力分散：模型在过长的上下文中可能忽略关键信息
  • 成本浪费：每个Token的推理都是有成本的
  • 隐私风险：不必要的代码传输增加了数据泄露风险

因此，上下文收集的核心挑战是在有限的窗口内选择最相关的代码片段。

6.5.2 代码切片技术

代码切片（Code Slicing）是将代码库分解为可管理片段的过程。常见的切片策略包括： 按语法结构切片

利用抽象语法树（AST）将代码按语法结构进行切分：

  • 函数级切片：每个函数作为一个独立的切片单元
  • 类级切片：每个类及其方法作为一个切片
  • 文件级切片：每个文件作为一个切片

函数级切片是最常用的粒度，因为函数是代码复用的基本单位，也是AI编程中最常见的操作对象。

按语义相关性切片

基于代码的语义相关性进行切分：

  • 调用关系切片：将被调用函数和调用者关联
  • 数据流切片：将数据的生产者和消费者关联
  • 修改历史切片：将频繁一起修改的文件关联（基于Git Co-Change分析）

6.5.3 AST分析

AST（抽象语法树）分析是理解代码结构的基础技术。通过AST，可以精确提取以下信息：
信息类型提取内容应用场景
符号表类名、函数名、变量名及其作用域符号解析、代码导航
类型信息参数类型、返回值类型、泛型参数类型检查、补全建议
控制流if/else、循环、try-catch结构代码路径分析
依赖关系import、require、include语句依赖图构建

AST分析的关键在于多语言支持。每种语言的AST结构和解析规则不同，需要为每种语言选择合适的解析器：

  • Java：JavaParser、Eclipse JDT
  • Python：ast模块、tree-sitter
  • TypeScript：TypeScript Compiler API、tree-sitter
  • Go：go/ast标准库
  • 通用方案：tree-sitter（支持30+种语言）

💡 技术建议： tree-sitter是目前最推荐的多语言AST解析方案。它提供统一的增量解析接口，支持30+种语言，且解析速度快、内存占用低。

6.5.4 符号索引与依赖图

符号索引

符号索引是将代码库中所有符号（类、函数、变量等）及其属性建立为可查询的索引结构。

索引结构示例：

Symbol {
  name: "UserService"
  kind: Class
  file: "src/service/user_service.go"
  line: 15
  signatures: ["func NewUserService(repo UserRepo) *UserService"]
  references: ["UserRepo", "UserModel"]
}

符号索引支持以下查询：

  • 查找符号定义
  • 查找符号引用
  • 查找符号的继承关系
  • 查找符号的调用者/被调用者
依赖图

依赖图（Dependency Graph）表示代码库中各模块之间的依赖关系。

依赖图的构建步骤：

  1. 解析所有文件的import/require语句
  2. 构建符号之间的引用边
  3. 计算模块间的依赖强度（引用次数）
  4. 检测循环依赖

依赖图在上下文收集中用于确定"哪些文件与当前编辑最相关"。例如，当开发者编辑UserService时，系统可以通过依赖图快速找到相关的UserRepo、UserModel、UserController等文件。

6.5.5 调用图分析

调用图（Call Graph）是依赖图的特化版本，专注于函数/方法之间的调用关系。

调用图的两种类型：

  • 静态调用图：基于代码分析构建，不考虑运行时行为
  • 动态调用图：基于运行时跟踪构建，反映真实的调用路径

对于AI编程助手，静态调用图是基础，动态调用图可以作为补充。

调用图在上下文收集中的应用：

  • 向上追溯：找到当前函数的调用者，理解函数的使用场景
  • 向下追溯：找到当前函数调用的子函数，了解函数的实现依赖
  • 影响分析：修改当前函数时，分析可能受影响的其他函数

6.5.6 动态上下文选择

动态上下文选择是根据当前编辑场景，智能选择最相关上下文的过程。

选择策略
策略触发条件选择逻辑
邻近优先任何场景优先选择当前文件和同目录文件
调用链优先函数编辑优先选择调用者和被调用函数
类型优先类型相关编辑优先选择类型定义和实现
历史优先频繁修改场景优先选择Git历史中频繁一起修改的文件
语义优先模糊搜索使用向量相似度匹配相关代码
选择流程 
用户输入/编辑 → 场景识别 → 策略选择 → 候选上下文收集 → 相关性排序 → 窗口预算分配 → 最终上下文

窗口预算分配是最后一步，根据模型的上下文窗口大小，为不同类型的上下文分配预算：

  • 当前文件：60%
  • 调用链相关文件：20%
  • 类型定义：10%
  • 其他相关：10%

6.5.7 多Agent协作架构

多Agent协作是2026年AI编程助手的核心能力之一。通过多个专业化Agent的协同工作，可以完成单个Agent无法胜任的复杂任务。 典型架构 
                    ┌──────────────┐
                    │  Plan Agent  │
                    │  (任务规划)   │
                    └──────┬───────┘
                           │ 任务分解
              ┌────────────┼────────────┐
              │            │            │
    ┌─────────▼──┐ ┌──────▼──────┐ ┌───▼────────┐
    │Architect   │ │ Coder Agent │ │Reviewer    │
    │Agent       │ │ (代码实现)   │ │Agent       │
    │(架构设计)   │ │             │ │(代码审查)   │
    └────────────┘ └─────────────┘ └────────────┘
Agent职责定义
Agent职责输入输出
Plan Agent任务规划与分解用户需求/Issue描述任务列表+依赖关系
Architect Agent架构设计与方案评审任务列表+代码库上下文架构方案+设计文档
Coder Agent代码实现架构方案+子任务代码变更+测试用例
Reviewer Agent代码审查与质量把关代码变更+审查规则审查意见+修改建议
协作流程
  1. Plan Agent接收用户需求，将其分解为可执行的子任务列表，明确每个任务的输入、输出和依赖关系
  2. Architect Agent分析子任务和代码库上下文，设计实现方案，包括模块划分、接口定义、数据流设计
  3. Coder Agent根据架构方案逐个实现子任务，生成代码变更和对应的测试用例
  4. Reviewer Agent对生成的代码进行审查，检查安全性、性能、代码风格等问题，给出修改意见
  5. 如果Reviewer Agent发现问题，将反馈给Coder Agent进行修正，循环直到审查通过
Agent通信协议

Agent之间的通信采用结构化的消息格式：

AgentMessage {
  from: AgentType
  to: AgentType
  type: "request" | "response" | "feedback"
  content: StructuredContent
  metadata: { taskId, iteration, timestamp }
}
容错机制
  • 超时控制：每个Agent的执行都有超时限制，超时后触发降级策略
  • 重试机制：失败的Agent请求最多重试3次
  • 人工介入：当Agent协作无法达成一致时，引入人工决策
  • 回滚机制：如果最终结果不满足要求，可以回滚到上一个稳定状态

💡 实践洞察： 多Agent协作不是简单的"多个Agent串联"，而是需要设计清晰的职责边界、通信协议和容错机制。Agent之间的信息传递应该结构化、可追溯，避免自然语言的歧义导致协作失败。

6.5.8 本章小结

上下文收集是AI编程助手的核心技术之一，涉及代码切片、AST分析、符号索引、依赖图和调用图等多种技术手段。动态上下文选择通过邻近优先、调用链优先、类型优先等策略，在有限的上下文窗口内选择最相关的代码片段。多Agent协作通过Plan Agent、Architect Agent、Coder Agent和Reviewer Agent的分工协作，可以完成复杂的编码任务。理解这些技术机制，是设计高效AI编程助手的关键。
