# 自查清单（每道确认点前强制过一遍）

> 使用说明：每道确认点之前逐条自查；不过关的修掉，或转成 TBD 告知用户。**每道确认点必须按 SKILL.md §8 的格式交一页摘要**，让用户看完摘要就能拍板。

## 确认点 0 前（需求确认：分支 A / B）

分支 A（需求调研）：
- [ ] 8 类问题都问到了吗（目标范围/利益相关者/用户场景/功能/非功能四类/约束依赖含数据/优先级/验收偏好）？
- [ ] 提问控制在 3 轮以内了吗？没问出来的部分是否按合理假设填了、标了 `[假设]`、进了 TBD（性质标"已假设"）？
- [ ] 优先级是否按 MoSCoW 换算（必须做→P0 / 应该做→P1 / 可以做→P2 / 明确不做→排除项候选）？
- [ ] **防"全是 Must"**：Must 超半数或全 Must 时，是否追问"只许做一半先砍哪些"并记 D-x？
- [ ] 前后回答冲突是否记 D-x 写明取舍（或升 TBD），没自行抹平？
- [ ] 每个决定记 D-x 了吗？带理由了吗？
- [ ] TBD 汇总成清单一次性交用户了吗？阻塞项和已假设项分开列了吗？

分支 B（已有文档拆解）：
- [ ] 六问查过缺口了吗（验收标准/非功能/异常流程/术语/排除项/**需求间矛盾**）？
- [ ] 缺口和矛盾一次性问完了吗？
- [ ] 原文档是结构化的话，转换表逐项落位了吗（模块→分组 / 需求→REQ / 用户故事→场景来源 / 优先级→P / 验收→AC 素材）？
- [ ] 原文档里"明确不做"的条目进排除项候选了吗（没有直接删掉吧）？

两条分支共同必过（v2.0）：
- [ ] **条目类型**：每条 REQ / BR 都标了类型（定义 / 约束 / 流程 / 判定 / 计算 / 推导）吗？后三类有没有被含糊标成"功能"从而躲过五要素？
- [ ] **可验收性**：每条需求都能回答"验收时怎么判"吗？答不出的降级为 TBD 标"需求未定"，并在原地写明"因需求未定，本期暂不做"了吗（**没静默丢下**）？
- [ ] **五要素草稿**：判定 / 计算 / 推导类规则，§5.1 填了触发 / 判定（含边界）/ 例外与覆盖 / 结果动作 / 位置与顺序吗？阈值写了来源吗？
- [ ] **边界值**：等于阈值、空值、最小值、最大量、并列 五种边界都问过了吗？
- [ ] **例外与反例**：每条判定类规则都写了"什么不算命中 / 什么不该做"吗？
- [ ] **需求间冲突**：同一对象有没有两个不同取值？当场定取舍并记 D-x 了吗（没含糊并存）？
- [ ] **排除理由**：每个 EX-x 都写了理由吗（会被误读成遗漏吗）？
- [ ] **需求对抗性审查 8 条**（模板 §13）逐条写结论了吗？不合格项的处置落地了吗？
- [ ] 术语全篇一致（无同物异名）、非功能有可测数字、依赖与前置条件写了吗？
