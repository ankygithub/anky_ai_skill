# 自查清单（每道确认点前强制过一遍）

> 使用说明：每道确认点之前逐条自查；不过关的修掉，或转成 TBD 告知用户。**每道确认点必须按 SKILL.md §8 的格式交一页摘要**，让用户看完摘要就能拍板。

## 确认点 0 前（需求确认：分支 A / B）

分支 A（需求调研）：
- [ ] 8 类问题都问到了吗（目标范围/利益相关者/用户场景/功能/非功能四类/约束依赖含数据/优先级/验收偏好）？
- [ ] 提问控制在 3 轮以内了吗？没问出来的部分是否按合理假设填了、标了 `[假设]`、进了 TBD（性质标"已假设"）？
- [ ] 优先级是否按 MoSCoW 换算（必须做→P0 / 应该做→P1 / 可以做→P2 / 明确不做→排除项候选）？
- [ ] **防"全是 Must"**：Must 超半数或全 Must 时，是否追问"只许做一半先砍哪些"并记 D-x？
- [ ] 前后回答冲突是否记 D-x 写明取舍（或升 TBD），没自行抹平？
- [ ] 每个决定记 D-x 了吗？带理由了吗？
- [ ] TBD 汇总成清单一次性交用户了吗？阻塞项和已假设项分开列了吗？

分支 B（已有文档拆解）：
- [ ] 六问查过缺口了吗（验收标准/非功能/异常流程/术语/排除项/**需求间矛盾**）？
- [ ] 缺口和矛盾一次性问完了吗？
- [ ] 原文档是结构化的话，转换表逐项落位了吗（模块→分组 / 需求→REQ / 用户故事→场景来源 / 优先级→P / 验收→AC 素材）？
- [ ] 原文档里"明确不做"的条目进排除项候选了吗（没有直接删掉吧）？

## 确认点 1 前（给人看的文档：README / 需求分析 / 设计决策 / 变更记录）

产出清单：
- [ ] **固定全套是否齐**（README / 1-需求分析 / 2-概要设计 / 3-详细设计 / 4-变更记录 / 5-验收报告 / ai-docs 四件）？缺一份即不合格。
- [ ] **3-详细设计 在吗**（数据库设计/表结构只在它里面，别处没有家）？
- [ ] 概要设计省略前，是否经用户确认（仅详细设计本身很小时允许）？
- [ ] **README 四要素齐了吗**（一句话定位 / 文档索引 / 执行入口 / AGENTS.md 写入提醒）？

需求分析完整性：
- [ ] 每条 REQ 有唯一编号 + 优先级（MoSCoW 换算）+ 一句话验收 + 场景来源（SC-x）？
- [ ] P0 条目附了 Given-When-Then 三行吗（标注"草案"）？
- [ ] "不做什么"逐条写了吗（含从 Won't 确认降落的条目，编号 EX-x）？
- [ ] **"以后做但非本期"的需求进 LAT-x 了吗**（没被误标成排除项或丢弃）？
- [ ] **业务规则节（BR 草稿）有了吗**——用户审需求分析时能看到这些规则？
- [ ] **风险节（RSK-x）有了吗**——死线紧/外部依赖不可控等调研期风险登记了？
- [ ] 非功能需求四类（性能/安全/兼容性/易用性）逐类过了吗？指标可测量吗？
- [ ] 利益相关者识别了吗（最终用户/拍板人/技术相关方/合规安全）？
- [ ] 术语表建了吗？全文一致吗？
- [ ] REQ 抽查过 INVEST 吗（按 REQ 语境裁剪：独立的/可谈的/有价值的/可估的/够小的/可测的）——不达标的拆分或合并了？
- [ ] 事实论断标了 `[有据]/[调研]/[经验]/[假设]` 吗？`[假设]` 都进 TBD 了吗（性质"已假设"）？

设计决策完整性：
- [ ] 每项选型绑定了理由 + 被否决的方案吗（只写"用 X"不写"为什么"不合格）？
- [ ] 模块职责一句话说得清吗？依赖没有环吧？
- [ ] 设计决策（AD）回链 REQ 了吗？
- [ ] 这份文件里只讲了"为什么"吧——类图、表结构这些 AI 干活用的细节没混进来（那些在 ai-docs 里）？
- [ ] **接口一致性抽查**：同一接口在详设、spec.md、架构图中出现的地方，方法/参数/错误码一字不差吗（抽查 ≥3 个）？
- [ ] **表结构格式抽查**：数据库设计的每张表是否独立成节（标题=表名+表注释）？字段表是否含字段名/类型/约束/字段注释？有没有把所有表挤进一张大表？

可读性（对照 `templates/_写作规范.md`）：
- [ ] 每节第一句直接给事实或判断（没有"下面介绍……"这种空话）？
- [ ] 没有万能开头结尾、空泛成就、程度副词堆砌、咨询黑话、空动词、说不清的"确保"？
- [ ] 每段抽象概括后面至少跟着一个具体数字或例子？
- [ ] 每张图后面都有"这张图怎么读"的文字（只有图没有解读不合格）？

## 确认点 2 前（给 AI 看的四份：ai-docs/）

一般项：
- [ ] 每个任务能独立完成、独立验证吗（完成标准可判定 + 有验证命令）？
- [ ] 每条 AC 都能机械判 pass/fail 吗（含边界值）？
- [ ] 验收断言只写在 acceptance-criteria.md 里吧（spec 和 test-plan 里没有第二份抄写）？
- [ ] 自测用例 100% 覆盖 AC 了吗（没有漏掉的、也没有没人认领的孤儿用例）？
- [ ] 每条"明确不做"都有对应的"系统不应"验收（AC-E）吗？
- [ ] 技术栈/版本/命令/错误码都是确定值吗（TBD 带默认建议）？
- [ ] spec.md 每条 REQ 都是"当…时，系统应…"句式吗？带 [ADDED] 标签吗？
- [ ] 架构级约束每条都配了"怎么检查违没违反"的方法吗？
- [ ] execution-plan 有执行纪律四件套（先定接口再写码/自查清单/Git 节奏/卡住 3 次报告）+ 串并行策略 + 工程结构 + 追踪矩阵吗？

装傻测试（核心闸门——假装只拿到 ai-docs/ 四份、完全不了解背景的执行者）：
- [ ] spec.md 里每条需求都有完整描述吗（把 docs/ 下的文档全删掉，每条 REQ 依然看得懂）？
- [ ] 有最小业务背景和术语表吗？
- [ ] 技术栈、框架、第三方依赖及版本都写死了吗？
- [ ] 目录结构、构建/启动/测试/Lint 命令、环境变量都写清了吗？
- [ ] 错误怎么处理写清了吗（错误码体系/重试/超时/幂等/降级）？
- [ ] 任务的步骤里内联了要用的接口签名、表结构、配置项吗？
- [ ] 全文搜一遍：四份文档里有没有引用 docs/ 下给人看的文档的地方（文件头"血缘"一行除外）？有就不合格。
- [ ] 有前端的话：页面契约（路由/元素/交互/五种状态）和颜色间距数值内联进去了吗？有 UI 类验收标准吗？

生成期对账（核心闸门——需求/详设 vs AI 文档必须对齐，防编号不一致与内容漂移）：

**① 需求 ↔ spec 对账（源头对齐）**
- [ ] spec 需求全集与 1-需求分析逐条对上吗：REQ-F 数量一致、无缺漏、无凭空新增（新增必须曾在确认点出现）？
- [ ] 排除项对齐：spec §5.2 禁止实现清单 = 需求分析 §7.3 EX-x 全集（一条不落、不多）？
- [ ] BR 对齐：spec §7 = 需求分析 §5 BR 草稿全集，表述一致（草稿里"如 5%"冻结时不能变成"6%"）？
- [ ] 边界值抽查：spec 里每个 REQ 的边界条件、枚举取值与需求分析原文一致（抽查 ≥3 条）？
- [ ] 术语对齐：spec 术语表 ⊆ 需求分析术语表 + 新增术语有定义，两边对同一词无不同解释？

**② 详设 ↔ spec 对账（契约对齐）**
- [ ] API 数量对齐：spec §6 契约数 = 3-详细设计 §3 接口数，编号一一对应（不允许 33 vs 34）？
- [ ] 表结构对齐：spec 引用的表 = 3-详细设计 §4.2 的表，数量一致、字段不漂移（改表必同步两边）？
- [ ] 错误码对齐：spec 错误码表 = 3-详细设计 §0.2 错误码，编码/消息/HTTP 状态一字不差？
- [ ] 枚举对齐：spec 枚举字典 = 3-详细设计 §0.3 枚举，取值一致？
- [ ] 技术栈对齐：spec §3 技术栈与详设技术选型一致（版本不许两处不同）？

**③ 编号一致性（防悬空引用与复用冲突）**
- [ ] 全库编号反查：spec 引用的每个 REQ/BR/AD/API/AC/TC 编号，在其权威处都存在（无悬空引用）？
- [ ] 无编号复用：同一编号未被两处用在不同对象上（如 RSK-1 不能在需求分析和 execution-plan 里指不同风险）？
- [ ] AC 编号语义：AC-x.y 的 x=REQ 组号；AC-E 关联 EX-x；TC 全部映射到 AC 且无孤儿用例？
- [ ] 追踪矩阵完整：REQ 列覆盖全部非 [REMOVED] 需求，AD/API/T/AC/TC 各列无空缺？

**④ 内容漂移哨兵（数量级口径一致）**
- [ ] 项目数字口径一致吗：模块数、API 数、REQ 数、AC 数在需求分析/概设/详设/导航里的数字互相吻合（数出 6 个模块，概设不能写 5 个）？
- [ ] 关键业务数字一致：并发量、数据量级、性能指标在需求分析、spec、验收标准里是同一个数？

## 交付后的变更

- [ ] 变更先记 4-变更记录，再动文档？
- [ ] 移除（REMOVED）写了理由和迁移说明吗？破坏性变更重走确认点 1 了吗？被移除的需求保留编号改标了吗（没物理删除吧）？
- [ ] 两组文档受影响条目一起升版了吗（版本号按 SKILL §9 规则：小改 minor / 动行为 major）？"与代码同步截止"更新了吗？
- [ ] README 的文档清单更新了吗？

## 每道确认点摘要本身（强制项，也应自查）

- [ ] 摘要是否一屏以内（SKILL.md §8 格式）？
- [ ] 风险是否从需求分析 §9 RSK-x 取（没现场编）？
- [ ] "等你拍板"是否只列 TBD 阻塞项、"可否决的假设"是否单列已假设项？
