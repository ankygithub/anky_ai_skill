# 模板：README-项目说明（文档组入口，所有项目都要有）

> 使用说明：`docs/README.md`，整个文档组的极简入口——**定位 + 指向导航**，不做完整索引（索引收敛到 `文档清单与导航.md` 一处，避免两份索引漂移）。叙述遵守 `_writing-guide.md`（`templates/_writing-guide.md`），保持一屏能读完。

---

# [项目名称]

## 1. 一句话定位

（这是什么、给谁用、解决什么问题。两三句，开篇即事实。）

## 2. 文档从哪读起

- 完整文档清单 / 各文档状态 / 角色阅读路径 / 项目数字速查 → **`文档清单与导航.md`**（唯一权威索引）
- 给人看的：1-需求分析（为什么做）→ 2-概要设计（怎么搭）→ 3-详细设计（怎么实现，**入口在 §1 架构与模块总览**；体量大时拆出 `3.1-模块设计` / `3.2-接口契约` / `3.3-数据设计` / `3.4-界面索引`，统一从主文档 §1.2/§1.3/§1.4 索引进入）；有前端界面时加读 6-界面说明书（界面长什么样、怎么操作）；7-用户手册（面向最终用户，需求基线冻结后填充）
- 给 AI 看的：`ai-docs/` 四件套

## 3. 执行入口（给新的编码会话）

1. 先读 `ai-docs/spec.md`（编码契约）。
2. 再读 `ai-docs/execution-plan.md` §1 执行纪律，按任务清单顺序执行。
3. 自测按 `ai-docs/test-plan.md`；验收对照 `ai-docs/acceptance-criteria.md`。
4. 任何变更：先记 `4-变更记录.md`，按追踪矩阵反查影响面，两组文档一起修订——禁止绕过变更记录直接改代码和文档。
5. 首版交付后一轮一轮追加的需求，走 `changes/`：见 `changes/README.md` 台账，每轮在 `changes/round-NN/` 内看讨论稿（`discuss.md`）、干净清单（`todolist.md`）、本轮自测（`test-plan.md`）。**裁定以本轮清单为准（后轮 > 前轮 > 主文档）**；**追加期本套文档一律不回写**——动了已定语义只在清单 §D 登记，等一个基线开发做完后做**基线重建**（据现有代码+全部文档重生成干净文档），旧整套文档归档到 `开发过程文档备份/baseline-vN/`。

> 若宿主项目存在 AGENTS.md / 项目规则文件，请把本节内容写入，保证每次会话自动加载。
