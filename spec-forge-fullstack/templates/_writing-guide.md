# 给人看的文档：写作规范（六维 + 去 AI 味红线）

> 本规范适用于 spec-forge 产出的全部给人看的文档（`docs/` 目录下所有文档）。每份文档交付前必须逐条自查。技术表格、编号条目不受叙述性规范约束；规范管的是"叙述性文字读起来像不像人写的"。

## 一、六维写作法（适配工程文档）

### 1. 声音（Voice）
工程文档的声音 = 严谨务实的工程师：说事实、给判断、不夸饰。

- ❌ 宣传腔：「本系统凭借其先进的技术架构，将成为行业标杆」
- ✅ 务实腔：「这个方案能扛住预估的 1000 QPS，代价是多部署一个节点」

### 2. 节奏（Rhythm）
叙述性段落（背景、理由、分析）长短句交替：短句 3-7 字承重，长句 15-30 字舒缓。关键信息用短句。写完读一遍，喘不过气的地方断句。表格、清单不受此限。

### 3. 结构（Structure）
结论先行，用内容本身的逻辑推进。

- ❌ 模板骨架外露：「首先……其次……此外……最后……综上所述」
- ❌ 元叙述：「下面我们来介绍……」「本章将详细说明……」（标题已说的，正文第一句不再重复）
- ✅ 章节第一句直接给事实或判断

### 4. 细节（Details）
每段抽象概括后至少配一个具体事实、数字或例子。「显著提升」→「处理时间从 4.2s 降到 1.1s」。数据不确定就用约数并标注 `[估算]`。

### 5. 分寸（Propriety）
修饰词留余地，技术结论不含糊。

- ❌ 完美的解决方案 / 彻底解决 / 极大地提升 / 卓越成效
- ✅ 当前可行的方案 / 问题得到有效缓解 / 处理时间从 X 降到 Y

注意：分寸只约束修饰词，不软化技术判断——设计取舍该明确就明确。

### 6. 金句（Sparkle）
设计类文档**可选**一处关键判断的提炼句，一句让人记住的精准判断（设计原则、取舍结论）。用不上一句也不勉强——工程文档以务实为准，修辞是锦上添花，不是义务。全文不超过两处，多了就是修辞堆砌。需求类文档不强求。

> 文风边界：本规范约束的是"给人看的文档"的叙述性段落。ai-docs 里那些会被人类读到的说明文字（如 spec.md 的 Why/What/Impact 节、各模板的使用说明）同样适用本规范——它们也是给人看的，只是比 docs/ 下的正文更克制、更短。

## 二、去 AI 味红线（交付前必查）

| 红线 | 病态示例 | 改法 |
|---|---|---|
| 万能开头/结尾 | 「在当前……形势下」「随着……的快速发展」「让我们共同努力」 | 从具体事实切入；实在话收尾 |
| 空泛成就 | 「取得了显著成效」「实现跨越式发展」 | 具体数字或事例 |
| 程度副词堆砌 | 「极大地」「显著地」「有效地」「全面地」 | 删掉，让事实说话 |
| 假大空归因 | 「行业专家认为」「业内人士表示」 | 给具体出处，否则删 |
| 管理咨询黑话 | 「赋能」「抓手」「底层逻辑」「心智」「颗粒度」「拉通」 | 换领域内真实用语（「闭环」「对齐」等在工程语境有既有含义时可用，禁止咨询腔贴皮） |
| 空动词 | 「进行分析」「开展调研」「实施优化」 | 直接用动词：分析、调研、优化 |
| 不可验证的确保 | 「确保用户体验良好」 | 可测量判据：「页面加载 ≤ 2s」 |
| 句末空洞拔高 | 「……奠定了坚实基础」「……彰显出……」 | 就此停住，或说下一步具体做什么 |
| 破折号/排比泛滥 | 一段 ≥3 个破折号；「不仅……而且……」连用 | 破折号最多保留一个；排比拆成两句 |
| 情感模板化 | 好事全「令人振奋」，坏事全「值得反思」 | 用动作、细节承载判断，不用情感标签 |

## 三、证据标注（让读者知道每句话的分量）

事实性论断按需标注来源强度：

| 标注 | 含义 | 适用 |
|---|---|---|
| `[有据]` | 有数据或原始需求文档支撑 | 性能指标、业务量、用户提供的数字 |
| `[调研]` | 有外部调研或公开资料支撑 | 竞品情况、行业惯例 |
| `[经验]` | 工程经验推断，未独立验证 | 架构选型理由、容量预估 |
| `[假设]` | 为补信息缺口做的假设 | 必须同步列入文档的 TBD 清单 |

禁止把 `[假设]` 和 `[经验]` 的论断写成既成事实。

## 四、图表规范

- 图表一律用 Mermaid（思维导图 `mindmap`、架构 `graph`、时序 `sequenceDiagram`、类图 `classDiagram`、ER `erDiagram`、状态 `stateDiagram-v2`、流程 `graph LR/TD`），禁止截图贴图。
- 每个图后面必须跟一段文字解读，图与文互相印证——只有图没有解读，或只有叙述该配图却没配，都不合格。
- 文字无法消除歧义的结构、流程、交互、状态，必须配图。
