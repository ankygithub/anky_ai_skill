# 模板：6-界面说明书（有前端时产出，人读）

> 使用说明：`docs/6-界面说明书.md`。**定位：人读版界面说明**——让没参与设计的人读一遍就明白"这系统长什么样、每页干什么、怎么用、能做成什么"。**不是**字段级穷举的界面规格书（那种机械归档没人读；原型本身就是最好的界面规格），也不是给最终用户的操作手册（那是 `7-用户手册.md`）。
>
> 取材：原型（`docs/原型/*.html`）+ `2-概要设计.md` §3.2 产品说明书 + `1-需求分析.md` 的 SC-x。**不复制视觉 token 数值**（颜色/间距内联在 `ai-docs/spec.md`，此处只引用口径）；**不写后端实现**（接口/表结构在 `3-详细设计.md`）。叙述遵守 `_writing-guide.md`（`templates/_writing-guide.md`）。
>
> 产出条件：项目有前端界面时产出；纯后端/无界面项目不产。状态流转：草稿 → 已冻结（确认点 1）。

## 1. 界面总览

一段话讲清：这个系统有哪些页面/视图，用户从哪进、主线怎么走。

```mermaid
flowchart LR
    A[主界面] --> B[二级页]
    B --> C[详情页]
```

（图后解读：入口在哪，主路径是哪条，哪些是分支。）

## 2. 逐页面说明

> 每页一小节，按"**这页为什么存在 → 长什么样 → 怎么用 → 支撑什么功能 → 没数据/出错时长什么样**"写。**叙述为主**；元素清单只列"人一眼找不到的"或"有状态变化的"（禁用、只读、徽标、选中态），不逐像素穷举。有原型截图就引用。

### 2.1 [页面名]

- **这页干什么**：一句话，对应哪条 SC-x。
- **界面构成**：一段话描述布局与关键元素；有状态变化的元素单独列出（例：保存按钮在未改动时置灰）。
- **怎么用**：主要操作路径一步步写；含快捷键、右键菜单、拖拽等。
- **支撑的功能**：回链 REQ-F-x.y——读这页能完成哪些需求。
- **空态与出错**：没数据时显示什么、操作失败时提示什么、无权限时怎样。
