# 模板：追加需求台账（产出 `docs/changes/README.md`）

> 使用说明：`docs/changes/README.md`。文档组交付后，**每一轮追加需求**在此登记一行——这是追加需求的唯一索引。
>
> 轮次目录结构：
>
> ```
> docs/changes/
> ├── README.md          # 本台账（唯一索引）
> └── round-NN/
>     ├── discuss.md      # 讨论稿：讨论过程 + 中立评审 + 参考素材 + 被否决项（可脏，可迭代）
>     ├── to-list.md      # 干净执行清单：只留结论（开发与核销的唯一依据）
>     ├── test-plan.md    # 自测计划：AI 自测，不留人工
>     └── assets/         # 参考素材片段备份（GitHub 代码、算法片段、截图）
> ```
>
> **裁定规则（硬性）**：冲突时 **后轮 > 前轮 > 主文档**（1-需求分析 / 2-概要设计 / 3-详细设计 / ai-docs）。任何覆盖必须显式标注"覆盖 X / 废弃 Y"，不许默默改写。
>
> **与主文档的关系**：**一律不回写**主文档（逐轮回写会与主文档反复冲突、变更细节越堆越难读）。基线开发做完后做一次**基线重建**：据"现有代码 + 全部既有文档 + 已核销轮次清单"重生成一套干净文档，旧整套文档（含已并入的轮次）归档到 `docs/开发过程文档备份/baseline-vN/`，**轮次编号继续递增**（跨基线全局唯一，不归零）。见 SKILL.md §9.3。
