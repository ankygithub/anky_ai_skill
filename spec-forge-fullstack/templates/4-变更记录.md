# 模板：4-变更记录（给人看的，必产）

> 使用说明：`docs/4-变更记录.md`。文档组交付后一切需求变更的**唯一入口**——先记变更，再改文档。这是它的核心价值：半年后能回答"后来为什么改成这样"。初始为空表。变更影响面用 `ai-docs/execution-plan.md` §5 追踪矩阵反查。

# 变更记录：[项目名称]

> 增量语义：**ADDED**（新增需求）/ **MODIFIED**（修改需求）/ **REMOVED**（移出需求）。

| 变更编号 | 日期 | **变更类型** | **破坏性** | 变更内容 | 原因 | REMOVED 必填：理由 + 迁移说明 | 影响范围（追溯编号） | 已修订文档及版本 |
|---|---|---|---|---|---|---|---|---|
| CHG-1 | | ADDED / MODIFIED / REMOVED | 是 / 否 | | | | REQ-F-2.1 → AD-2 → T-5 → AC-3.1 / TC-9 | spec.md v1.1、acceptance-criteria.md v1.1、1-需求分析 v1.1 |

**变更规则**：

- REMOVED 变更缺"理由 + 迁移说明"→ 拒绝进入修订（防需求悄悄消失、下游代码成孤儿）
- 破坏性 = 是 → 必须重走确认点 1，用户点头后方可修订
- REMOVED 生效后，spec.md 中对应 REQ 条目保留编号、改标 [REMOVED] 并注明 CHG-x，**禁止物理删除**（编号永不复用，历史可追溯）
- 两组文档受影响条目同步升版；更新各文档"与代码同步截止"标注；更新 README 文档索引
