# 质量检查清单

在输出 PROJECT.md 给用户确认前，必须逐项检查。

## 一、读者路径检查

- [ ] 是否从读者熟悉的问题开始？
- [ ] 是否避免一上来堆术语？
- [ ] 是否有从入门到深入的递进？
- [ ] 每章是否都有明确的"读者收益"？

## 二、内容完整性检查

- [ ] 是否覆盖主题的核心概念？
- [ ] 是否覆盖常见误区？
- [ ] 是否覆盖实践或应用？
- [ ] 是否覆盖边界和局限？
- [ ] 是否有案例/练习/图表规划？

## 三、资料支撑检查

- [ ] 每个关键章节是否有 research 文件支撑？
- [ ] 是否标注了资料可信度（A/B/C/D）？
- [ ] 是否存在资料不足的章节？（需标注"待补充"）
- [ ] 是否存在待验证的事实？

## 四、章节边界检查

- [ ] 各章节是否职责清晰？
- [ ] 是否存在重复内容？
- [ ] 是否存在跳跃过大的章节？
- [ ] 多 Agent 分工是否合理？（关联章节是否分配给同一 Agent）

## 五、可写性检查

- [ ] 每章是否有足够素材写成长内容？
- [ ] 是否知道每章应该用什么表达方式？
- [ ] 是否知道哪些地方需要图表？
- [ ] 是否知道哪些地方需要案例？

## 六、标题质量检查

- [ ] 章节标题是否避免"概述""介绍""基础知识"等弱标题？
- [ ] 标题是否像书的标题，而非资料夹名称？
- [ ] 标题是否用问题/读者收益/冲突来命名？

## 七、证据矩阵检查

- [ ] 核心论点是否都有资料支撑？
- [ ] 是否有高风险内容未标注？
- [ ] 是否避免了将 C/D 级资料作为核心依据？

## 八、网络搜索验证检查

- [ ] 每个调研维度是否执行了至少 2 个搜索引擎的搜索？
- [ ] 关键事实是否都有可访问的 URL 来源？
- [ ] 具体数据是否标注了来源和获取时间？
- [ ] 技术类内容是否验证了最新版本信息？
- [ ] 不同来源矛盾处是否已并列标注？

## 检查结果总结

如以上有未通过项，先修正后再输出给用户。
