# 书籍大纲规划技能

将主题转化为完整的可执行书籍规划（PROJECT.md + 调研报告）。

## 核心流程

```
阶段0：意图澄清与类型识别 → 阶段1：深度调研 → 阶段2：大纲规划 → 阶段3：用户确认
```

### 阶段0：意图澄清与类型识别

**收集信息**（未提供则询问，已提供则跳过）：
- 主题（必须）
- 目标读者（可选，可推断）
- 内容深度 L1-L4（默认 L2）
- 篇幅预期（默认中等）
- 风格偏好（默认混合）
- 特殊素材路径（可选）

**类型识别** — 匹配 14 类书籍：

| 代号 | 名称 | 触发特征 |
|------|------|----------|
| T01 | 新技术学习类 | 技术术语/框架/平台 |
| T02 | K12 学习辅导类 | 试卷/错题/薄弱点 |
| T03 | 应试备考指南类 | 考试名+备考/复习 |
| T04 | 科普知识类 | 科学概念/自然现象 |
| T05 | 历史深度解读类 | 历史事件/人物/朝代 |
| T06 | 商业案例分析类 | 公司+商业/案例/战略 |
| T07 | 个人成长方法论类 | 效率/习惯/思维/自我提升 |
| T08 | 产品工具手册类 | 软件/工具+教程/手册 |
| T09 | 地方文化旅行指南类 | 地名+旅行/文化 |
| T10 | 文学写作类 | 小说/散文/诗歌/创作 |
| T11 | 亲子教育类 | 家庭教育/儿童心理 |
| T12 | 职业技能成长类 | 职业路径/岗位能力 |
| T13 | 生活实用指南类 | 健康/理财/饮食/运动 |
| T14 | 综合型专题书 | 跨多类型复杂主题 |

识别后告知用户，支持手动调整。

**输出**：`analysis/pre-analysis.md`，格式：

```markdown
# 初始分析卡
## 书籍类型：[自动判定]
## 判定依据：[特征]
## 目标读者画像：[...]
## 内容深度：L1/L2/L3/L4
## 风格基调：[...]
## 核心主题清单：[3-5个]
## 调研维度列表：[N个]
## 预估篇幅：[X万字/X章]
## 特别注意事项：[...]
```

用户确认后进入阶段1。

### 阶段1：深度调研

**步骤 1.1：加载调研模板**

读取 `references/research-templates/T{编号}-{类型}.md`（根据阶段0识别的类型），获取该类型的 8-10 个调研维度。
跨类型时组合多套模板，去除重复维度。

**步骤 1.2：生成搜索关键词**

每个调研维度自动生成 3-5 组关键词，覆盖：
- 中文核心词 + 英文专业词 + site限定词
- 示例：`"K8s 性能优化 最佳实践 2025 2026"` `"Kubernetes performance benchmark"`

**步骤 1.3：执行网络搜索**

- 至少 2 个搜索引擎
- 技术类优先近12个月资料
- 一手信源优先（官方文档/论文/GitHub）
- 矛盾说法并列标注

**步骤 1.4：写入调研报告**

读取 `references/research-report-template.md` 获取调研报告的标准结构，按此格式保存至 `research/YYYY-MM-DD-{维度}.md`。

**重要原则**：调研是为了支撑 PROJECT.md 的内容。PROJECT.md 的"信息来源"列应直接写入调研结论摘要，而非仅写文件路径，确保 PROJECT.md 是自包含文档。

可信度分级：
| 等级 | 类型 | 使用 |
|------|------|------|
| A | 官方文档/论文/标准 | 核心依据 |
| B | 专家博客/技术大会 | 重要参考 |
| C | 社区讨论/问答 | 案例补充 |
| D | 未验证观点 | 仅线索 |

**步骤 1.5：交叉验证**

所有维度完成后，检查矛盾、依赖遗漏、单一信源、覆盖缺口，输出 `research/cross-check.md`。

**步骤 1.6：调研汇总**

输出 `research/research-synthesis.md`，包含：
- 读者画像
- 核心问题地图
- 知识结构地图
- 证据矩阵
- 章节候选池
- 进入规划条件检查清单

### 阶段2：大纲规划

**步骤 2.1：创建项目目录**

```
{项目目录}/
├── PROJECT.md
├── analysis/pre-analysis.md
├── research/*.md
│   ├── YYYY-MM-DD-{维度}.md
│   ├── cross-check.md
│   └── research-synthesis.md
```

**步骤 2.2：生成 PROJECT.md**

读取 `references/project-template.md` 获取 PROJECT.md 的完整结构和模板，输出必须包含以下所有模块：
- 项目元信息
- 书籍定位（是什么、不是什么、读完后的变化）
- 读者画像
- 内容策略
- 章节大纲表（含 Part/节号/标题/核心内容/读者收益/信息来源/类型标签/前置依赖）
- 知识递进路线
- 读者问题地图
- 证据矩阵
- Agent 并行分工方案
- 调研资料索引
- 术语表
- 图表与组件规划（优先SVG格式，标注"建议SVG"或"建议ASCII"）
- 风险清单
- 进度追踪表
- 用户确认区
- **附录：调研资料索引**（参考资料存档在附录，不跳转外部文件）

**步骤 2.3：单章 Mini-Plan**

每章在 PROJECT.md 中附详细规划：
```
### Chapter X: 标题
- 核心论点（≤30字）
- 读者读完能做什么
- 关键案例/数据
- 引用调研文件
- 与前章衔接/后章铺垫
- 预估字数/风险点
```

**步骤 2.4：质量自检**

读取 `references/quality-checklist.md` 逐项检查，未通过则先修正再输出给用户。

### 阶段3：用户确认

输出精简版大纲给用户确认：
- 书籍定位
- 大纲结构（Part → 章节 → 一句话说明）
- 建议重点写深的部分
- 需要确认的问题

确认后标记 PROJECT.md 状态为 `✅ 已确认，可交付写书技能使用`。

## 网络搜索策略

按类型采用不同搜索策略：

| 类型 | 优先目标 | 时效 |
|------|---------|------|
| T01 新技术 | 官方文档/GitHub/技术博客 | 近12月 |
| T02 K12 | 课标官网/教材/真题库 | 近3年 |
| T03 应试 | 考试院/大纲/真题 | 最新 |
| T04 科普 | 学术期刊/科研机构 | 近5年 |
| T05 历史 | 史料库/学术论文 | 注意最新研究 |
| T06 商业 | 财报/新闻/行业分析 | 近1-2年 |
| T08 产品 | 官方文档/更新日志 | 最新 |

防幻觉机制：
- 事实必须附带 URL 来源
- 数据标注来源和获取时间
- 模型推断标注"待验证"
- 过期内容标注版本差异

## 文件参考指南（渐进式加载）

以下文件在对应流程步骤中按需加载，不要一次性全部读取。

### 阶段1 深度调研时加载
- `references/research-templates/T{编号}-{类型}.md` — 调研维度模板，根据类型识别结果读取对应文件
- `references/research-report-template.md` — 调研报告的标准结构，写入 research 文件前读取

### 阶段2 大纲规划时加载
- `references/project-template.md` — PROJECT.md 完整模板和结构说明，生成规划前读取
- `references/quality-checklist.md` — 大纲质量自检清单，输出用户确认前执行检查
