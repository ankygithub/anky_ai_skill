# 自动触发场景详细说明

本文档为 trae-mem0 skill 的自动触发场景提供详细说明。当 AI 需要深入理解某个触发场景时，阅读对应章节。

## 一、自动保存场景详解

### 场景 1：用户纠正

用户纠正是最重要的记忆来源之一。AI 被纠正后，不仅要立即改正，还要把纠正内容存为记忆，避免下次再犯同样错误。

**典型对话模式**：
- "不对，这个项目用的是 pnpm 不是 npm"
- "不是这样的，应该是..."
- "Actually，这里应该用枚举而不是常量"
- "你错了，这个 API 已经废弃了"
- "纠正一下，我们的命名规范是驼峰不是下划线"

**记忆内容结构**：
```
"纠正: {用户指出的错误认知} → 正确做法: {正确的做法或知识}"
```

**作用域判断**：
- 如果纠正的是项目特定内容（如项目命名规范）→ project
- 如果纠正的是通用知识（如某个 API 的正确用法）→ global

### 场景 2：Bug 修复

当定位到 Bug 根因并完成修复后，这是一个宝贵的记忆点。记录下根因和方案，未来遇到类似问题可以快速解决。

**保存时机**：确认 Bug 已修复、测试通过后立即保存

**记忆内容结构**：
```
"Bug: {Bug 现象} → 根因: {根本原因分析} → 方案: {具体修复方案}"
```

**最佳实践**：
- 包含具体的错误信息关键词，方便后续搜索
- 标注涉及的文件路径
- 如果是环境相关的 Bug，加上 env 标签

### 场景 3：项目约定

项目约定包括命名规范、架构原则、代码风格、框架选择、依赖版本约定等。

**典型场景**：
- "我们统一用 Utils 后缀"
- "这个项目约定用 Composition API"
- "组件统一放在 src/components/ 下"
- "数据库用 PostgreSQL 15"

**记忆内容结构**：
```
"约定: {具体约定内容} — 适用范围: {范围说明}"
```

### 场景 4：用户偏好

用户的偏好是跨项目通用的记忆，非常重要。

**典型场景**：
- "我喜欢用 pnpm"
- "我习惯 2 空格缩进"
- "我偏向用 TypeScript"
- "测试我用 Vitest"
- "提交信息我用中文写"

**记忆内容结构**：
```
"偏好: {用户偏好的具体内容} — 上下文: {产生偏好的场景}"
```

### 场景 5：架构决策

记录架构决策时，不仅要记结论，还要记理由和备选方案，这对未来类似决策很有参考价值。

**典型场景**：
- "选用 React Query 而不是 SWR，因为..."
- "决定用 monorepo 架构，因为..."
- "选型 PostgreSQL 而不是 MySQL，因为..."

**记忆内容结构**：
```
"决策: {决策内容} | 理由: {选择理由} | 备选: {备选方案及未选原因}"
```

### 场景 6：隐性知识

隐性知识是指那些"不写在文档里但实际存在"的知识。这类知识最容易丢失，也最值得记忆。

**典型场景**：
- "这个模块有个隐藏的配置项..."
- "这个 API 有个奇怪的边界情况..."
- "这个 workaround 是因为底层库的 Bug..."
- "这个第三方服务的免费版有调用次数限制..."

**记忆内容结构**：
```
"知识点: {具体内容} — 涉及: {相关文件或模块}"
```

### 场景 7：关键词触发

当用户明确表达了"要记住"的意图时，无条件保存。

**触发词列表**：
- 中文：记一下、记住、存储、存一下、别忘了、以后注意、牢记、记录下来
- 英文：mark、remember、save this、keep this、note this

**处理方式**：将用户指示要记住的内容原样保存，标签加 `explicit` 标记

### 场景 8：任务完成

重要任务完成后，保存一个摘要供后续参考。

**保存时机**：
- 完成了新功能的开发
- 完成了重构
- 完成了性能优化
- 完成了文档撰写

**记忆内容结构**：
```
"任务完成: {功能/任务摘要} | 关键文件: {主要涉及文件} | 注意事项: {后续需要注意的点}"
```

### 场景 9：环境配置

环境配置类的信息很容易被遗忘，但重新搭建环境时又特别需要。

**典型场景**：
- "安装了 Node.js 18"
- "配置了 ESLint + Prettier"
- "设置了环境变量 DATABASE_URL"
- "初始化了 Git 仓库"
- "安装了 Redis"

**记忆内容结构**：
```
"环境配置: {具体配置内容} — 目的: {配置的目的或背景}"
```

## 二、自动召回场景详解

### 场景 1：会话开始

这是最重要的召回场景。每次新对话开始时，AI 应自动加载当前项目的相关记忆，让自己快速"进入状态"。

**执行流程**：
1. 获取当前工作目录名作为项目名
2. 调用 `search --query "{项目名} {技术栈关键词}" --scope all --limit 10`
3. 将搜索结果中的关键信息注入到当前上下文
4. 如果搜索结果为空，说明是新项目，无需加载

**搜索建议**：
- 查询词可以包含项目名 + 主要技术栈
- 例如当前项目是 TraeTools，技术栈是 Python
- 搜索 `"TraeTools Python 约定 决策"`

### 场景 2：相似任务

当 AI 发现当前任务与历史记忆相似时，主动搜索相关记忆。

**判断依据**：
- 操作的文件与历史记忆中的相关文件匹配
- 任务的类型（如"添加 API"、"修复 Bug"）与历史记忆匹配
- 用户问的问题与历史记忆内容相似

### 场景 3：用户提及过去

当用户提到过去的事情时，AI 应主动搜索相关记忆。

**触发词**：
- 中文：还记得、之前、以前、上次、曾经、原来、早前
- 英文：remember when、last time、previously、before

### 场景 4：遇到错误

当命令执行失败、出现异常堆栈时，AI 应主动搜索相似错误。

**搜索策略**：
- 提取错误信息中的关键错误码或错误信息片段
- 限制作用域为 project，因为环境特定的错误最有价值

### 场景 5：不确定时

AI 不应在不确定时盲目猜测或立即问用户，而应先查记忆。

**典型场景**：
- 不确定项目用什么包管理器
- 不确定项目用什么测试框架
- 不确定用户的命名偏好
- 不确定项目的目录结构约定

**优先级**：查记忆 > 查文档 > 问用户

### 场景 6：关键词触发

当用户明确要求查记忆时。

**触发词**：
- 中文：查一下、看看之前、有什么记忆、搜索记忆、翻一下
- 英文：recall、memory、search memory、what do you know about
