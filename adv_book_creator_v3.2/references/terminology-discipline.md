# 术语纪律规范（术语锁定 + 一致性）

> 目的：治 AI 写书时的"解释性改写"毛病——把行业标准术语自造成近义白话。
> 真实事故：CDC（数据仓库里的变更数据捕获）被写成"抓变化"；Kafka 被写成"管道"。
> 这类词**不算错，但出戏**：懂行的读者立刻感到作者不专业，不懂行的读者学不到正确的词，将来查资料、搜索都对不上。
>
> 适用范围：技术书、教材、行业手册尤其重要；纯文学/散文可弱化。

## 一、三条硬规则

1. **领域通用词优先**：该领域已通用的说法（判据见第二节体裁映射），**必须直接用**，不得自造替代词。
   - 技术书 ✅ 变更数据捕获（CDC）/ 消息队列（Kafka）；❌ 抓变化 / 管道
   - 写作书 ✅ 叙述视角 / 叙事弧；❌ 看事情的框框 / 故事走势线
2. **首次出现给足信息**：术语第一次出现时给全称/对照，之后可只用简称。
   - 技术/科普：给中英对照 `中文名（English，全称）`，例：变更数据捕获（CDC，Change Data Capture）
   - 方法/技艺、人文：给一次完整定义或出处即可，不必英文
3. **同一概念全书同一词**：一旦锁定，全书不得换说法。禁止"变更数据捕获"和"抓变化"混着用。

## 二、体裁映射（"什么算标准词"按书籍类型定）

**原则跨体裁成立**（用领域通用词、不自造、全书统一），但"通用词"的具体判据随体裁变。规划阶段先定 `PROJECT.md` 的**书籍类型**，再按档执行：

| 体裁档 | "标准词"= | 中英对照 | 例 |
|---|---|---|---|
| **技术/专业** | 行业标准译名 | 需要 | CDC、Kafka、幂等、背压 |
| **方法/技艺** | 学科通用概念 | 可不要 | 叙述视角、叙事弧、场景与概述、五感描写 |
| **商业/观点** | 通用商业词（忌黑话） | 可不要 | 现金流、毛利、渠道；忌"赋能/抓手/闭环" |
| **人文/叙事** | **不强制术语表**（改"用词台账"） | 不要 | 只统一人名/地名/关键物件的固定写法 |
| **科普** | 科学名词标准译名 | 需要 | 熵、光合作用、相对论 |

- **技术/科普**：术语表 + 中英对照是刚需——读者要能拿去搜。
- **方法/技艺**（如写作书）：术语表存"学科通用概念"，**禁自造白话**（"看事情的框框"≠叙述视角）。
- **人文/叙事**：不强设术语表，改维护一份"**用词台账**"——只钉人名、地名、专有物件的固定写法，避免前后不一。

## 三、术语表（结构，落在 PROJECT.md）

规划阶段即建立，写作与审查都以它为准：

| 中文标准名 | 英文 | 全称/说明 | 首次出现章 | 禁用同义词 |
|---|---|---|---|---|
| 变更数据捕获 | CDC | Change Data Capture | 第 5 章 | 抓变化、抽取变更 |
| 消息队列 | Kafka | 分布式流处理平台 | 第 5 章 | 管道、消息通道 |

- **禁用同义词列是重点**：把 AI 容易自造的说法显式钉死，写作时等于贴了封条。
- 术语表由规划 Agent 起草，**用户确认后锁定**；写作中若确需新增术语，先补进表再使用。

## 四、哪些词必须进术语表

按优先级，至少要覆盖：

1. **技术专有名词**：框架、协议、算法、设计模式（Kafka、CDC、CAP、B+ 树……）
2. **有标准译名的通用概念**：幂等、事务、背压、熔断、限流
3. **本书自造/约定的核心概念**：作者若自创了概念，必须显式定义并全书统一（这是"合法自造"，但要声明）
4. **易混淆近义词对**：并发≠并行、延迟≠延时、吞吐量≠带宽——锁死用哪个

## 五、采集阶段的术语侧产

素材采集时顺手记录：素材里出现的**标准术语与英文原文**（权威来源的用词最可信）。
采集 Agent 在素材文件头部追加一行：

```
术语：变更数据捕获(CDC)、幂等(idempotent)
```

主流程汇总各章术语 → 规划 Agent 合并去重 → 用户确认 → 写入术语表。这也是采集"顺带产出"的一部分，不额外增加搜索。

## 六、判据速查（拿不准时问自己）

- 这个词，**百度/谷歌搜原意能搜到吗**？搜不到 → 很可能是自造，改回标准词。
- 如果读者是**该领域的从业者**，他会不会觉得这个词别扭？会 → 改。
- 这个词，**英文原文是什么**？说不出英文 → 多半是自己编的。

> 术语纪律的**执行**归「资深编辑对抗审查」（见 `editor-review.md`）：写作 Agent 自律锁定，编辑 Agent 独立查违规。
