## 1. 框架概述

### 1.1 设计哲学

十层技术框架采用**由表及里、由技入道**的分层分析方法：

```
┌─────────────────────────────────────┐
│  Layer 09-10: 主题与体验（道/效果）   │  ← 最抽象，最核心
├─────────────────────────────────────┤
│  Layer 07-08: 修辞与场景（艺/表现）   │
├─────────────────────────────────────┤
│  Layer 05-06: 叙事与语言（法/工具）   │
├─────────────────────────────────────┤
│  Layer 03-04: 人物系统（魂/内容）     │  ← ⭐核心层
├─────────────────────────────────────┤
│  Layer 01-02: 工程与情节（骨/结构）   │  ← 最具体，最基础
└─────────────────────────────────────┘
```

### 1.2 分析目标

每层分析都追求四个核心产出：

| 产出项 | 说明 | 用途 |
|--------|------|------|
| **现象描述** | 客观观察到的特征 | 建立事实基础 |
| **典型证据** | 具体的原文例子 | 验证和示范 |
| **仿写规则** | 可操作的创作原则 | 指导实践 |
| **稳定度判断** | 特征的一致性评估 | 确定可复用性 |

### 1.3 双视角要求

每个分析层都必须同时提供：

- **技术侧（Technical）**：量化数据、结构模式、可复现的设计原则、参数化描述
- **文学侧（Literary）**：审美效果、读者心理、艺术表达的独特性、感性评价

## 2. 层级详细说明

### Layer 01: 作品工程层 (Engineering)

**定位**: 最基础的"骨架"分析  
**核心问题**: 这本书是如何被"建造"的？

#### 关键分析项

| 分析维度 | 量化指标 | 质性评估 |
|---------|---------|---------|
| 章节长度 | 平均值/中位数/标准差/分布 | 波动规律 |
| 标题风格 | 各类型占比统计 | 分类合理性 |
| 卷结构 | 每卷章节数/切换频率 | 结构逻辑 |
| 功能分布 | 各功能类型占比 | 配置效率 |
| 开篇方式 | 类型判定 | 吸引力评估 |
| 结尾钩子 | 各类型占比 | 悬念管理 |

#### 输出示例片段

```json
{
  "chapter_length_stats": {
    "avg_words": 3200,
    "median": 3000,
    "std_dev": 800,
    "distribution_pattern": "normal_with_heavy_tail"
  },
  "title_style_distribution": [
    {"type": "事件型", "count": 45, "percentage": 45}
  ]
}
```

#### 与其他层的关系
- **向上支撑** → Layer 02 (情节): 章节工程决定了情节展开的节奏容器
- **向下依赖** → 无（最底层）
- **横向关联** → Layer 05 (叙事): 工程结构影响叙事视角选择

---

### Layer 02: 情节结构层 (Plot)

**定位**: 故事的"肌肉"系统  
**核心问题**: 故事是如何推进和张弛的？

#### 关键分析项

| 分析维度 | 方法论 |
|---------|--------|
| 情节模板 | 五段式拆解（触发/发展/中段/转折/收束） |
| 冲突触发 | 外部vs内部冲突分类与比例 |
| 反转机制 | 五种反转类型及使用频率 |
| 高潮结构 | 铺垫-汇聚-层次-释放-余波 |
| 伏笔管理 | 三级伏笔（短/中/长程）及回收率 |
| 爽点密度 | 分布曲线绘制 |
| 压抑释放周期 | 微观/宏观周期参数 |

#### 仿写规则示例

```
【战斗升级模板】（源自某书Layer02分析）
触发: 主角遭遇实力强于自己的对手（差距不超过3倍）
发展: 
  - 试探阶段（1-2个回合，展示双方实力对比）
  - 压迫阶段（主角处于下风，但未受重创）
  - 觉醒契机（外部刺激或内部顿悟）
转折:
  - 突破限制（新能力/隐藏底牌/战术变化）
  - 扭转局势（从被动转为主动）
收束:
  - 击败对手（但不赶尽杀绝）
  - 收获（经验/声望/物品/信息）
  - 新危机预告（引出下一个更强的对手）

稳定度: 高（全书80%以上的战斗遵循此模板）
变体: 可通过改变"觉醒契机"的类型来创造多样性
```

### Layer 03: 主角伦理与行动哲学层 (Protagonist) ⭐核心

**定位**: 作品的"灵魂"所在  
**核心问题**: 主角是谁？TA如何做决定？

#### 九维坐标系统

| 维度 | 1分端 | 10分端 | 分析要点 |
|------|-------|--------|---------|
| 道德 | 极端利己 | 圣人级利他 | 底线、压力测试、演变 |
| 利己利他 | 纯粹利己 | 纯粹利他 | 动机纯度、伪利他检测 |
| 主动被动 | 完全被动 | 极度主动 | 掌控感、计划性 |
| 情绪 | 极度理性 | 极度感性 | 表达方式、决策影响 |
| 底色 | 黑暗 | 光明 | 世界观、自我对话 |
| 智识 | 平庸 | 天才 | 解决方式、盲区 |
| 欲望 | 清心寡欲 | 野心勃勃 | 核心欲望、异化风险 |
| 社交 | 极度社恐 | 社交达人 | 舒适区、孤独感 |
| 成长 | 静态 | 剧烈成长 | 轨迹、代价、对比 |

#### 决策模式矩阵

六种典型场景 × 决策偏好 = 36格决策画像

```

  "power_disadvantage": {

    "case_study": "第23章面对赵长老时选择暂时撤退",
    "success_rate": "85%"
  }
}
```

### Layer 04: 人物关系与群像层 (Characters)

**定位**: 人物生态系统  
**核心问题**: 除了主角，还有谁？他们如何互动？

#### 配角功能配置表

| 功能类型 | 典型特征 | 退出方式 | 占比建议 |
|---------|---------|---------|---------|
| 引路人 | 强于主角 | 牺牲/离开/转化 | 1-2人 |
| 战友 | 能力互补 | 并肩到底/牺牲 | 2-4人 |
| 知己 | 理解本质 | 长伴/分离 | 1-2人 |
| 搞笑担当 | 调节气氛 | 贯穿全程 | 1-2人 |
| 对照镜 | 对比突出 | 多种结局 | 1-2人 |
| 工具人 | 功能性 | 用完即弃 | 按需 |

#### 反派深度评分标准

```
1-3分: 工具反派，为阻碍而存在
4-6分: 有背景故事，动机可理解
7-9分: 复杂动机体系，可能令人同情
10分: 具有哲学深度，可与主角媲美
```

| 第三人称全知 | ★★ | ★★★★★ | 史诗/复杂剧情 | 高 |

```
        读者知道更多          角色知道更多
```

### Layer 06: 语言风格层 (Language) ⭐核心

**定位**: 作者指纹的技术层面  
**核心问题**: 文字本身有什么特点？

#### 可量化指标体系

```python
# 伪代码示例：语言风格量化
class LanguageAnalyzer:
    def analyze_sentence_length(self, text):
        return {
            'avg': calculate_average(text),
            'median': calculate_median(text),
            'std': calculate_std(text),
            'distribution': classify_distribution(text)
        }
    
    def analyze_vocabulary(self, text):
        return {
            'richness': unique_ratio(text),
            'top_content_words': frequency_analysis(text, n=50),
            'technical_density': jargon_count(text) / total_words
        }
    
    def analyze_punctuation(self, text):
        return {
            'comma_density': count(',', text) / word_count,
            'exclamation_rate': count('!', text) / sentence_count
        }
```

#### 词汇偏好分析框架

| 分析维度 | 子维度 | 输出形式 |
|---------|--------|---------|
| 高频实词 | 动词/形容词/名词 TOP列表 | 列表+解读 |
| 特殊词汇 | 黑话/自造词/术语 | 词典式 |
| 文白比例 | 古今成分占比 | 百分比 |
| 比喻取材 | 来源域分布 | 饼图+分析 |
| 禁忌词 | 回避/故意使用 | 清单 |

### Layer 09: 主题母题与价值观层 (Themes)

**定位**: 思想内核  
**核心问题**: 这本书到底想表达什么？

#### 价值冲突矩阵构建方法

```
步骤1: 识别书中至少3组对立价值观
步骤2: 通过主角的选择行为确定作者的立场
步骤3: 绘制对立轴，标注偏向和动态变化
步骤4: 检验一致性（是否前后矛盾？）
步骤5: 识别灰色地带和复杂情况
```

#### 主题深度等级

| 等级 | 特征 | 处理方式 |
|------|------|---------|
| 表层 | 明确说出，单维度 | 直接归纳 |
| 中层 | 通过情节体现，多维度 | 归纳+例证 |
| 深层 | 从未明说，渗透全文 | 推断+证据链 |
| 核心 | 可能作者本人也未完全意识 | 解读+验证 |

## 3. 层间关系图谱

### 3.1 垂直依赖关系

```
Layer 10 (体验)  ← 依赖于以上所有层的综合效果
    ↑
Layer 09 (主题)  ←  受 Layer 03(人物) 和 Layer 02(情节) 深刻影响
    ↑
Layer 08 (场景)  ←  受 Layer 06(语言) 和 Layer 05(叙事) 支撑
Layer 07 (修辞)  ←  建立在 Layer 06(语言) 基础上
    ↑
Layer 06 (语言)  ←  基础表达工具
Layer 05 (叙事)  ←  技术实现手段
    ↑
Layer 04 (人物)  ←  与 Layer 03 共同构成内容核心 ⭐
Layer 03 (主角)  ←  内容核心 ⭐
    ↑
Layer 02 (情节)  ←  骨架，承载所有上层
Layer 01 (工程)  ←  最基础容器
```

### 3.2 横向关联关系

| 强关联对 | 关系性质 | 说明 |
|---------|---------|------|
| L01 ↔ L02 | 结构-内容 | 工程结构决定情节展开方式 |
| L03 ↔ L04 | 核心-外围 | 主角决定配角配置逻辑 |
| L05 ↔ L06 | 形式-载体 | 叙事视角影响语言选择 |
| L06 ↔ L07 | 基础-升华 | 语言是修辞的素材 |
| L07 ↔ L08 | 抽象-具体 | 修辞在场景中落地 |
| L09 ↔ L10 | 因-果 | 主题决定体验方向 |

### 3.3 分析顺序建议

**推荐顺序**: L01 → L02 → L03 → L04 → L05 → L06 → L07 → L08 → L09 → L10

**理由**: 
1. 先建立基础认知（工程/情节）
2. 再深入核心（人物）
3. 然后分析技术实现（叙事/语言/修辞/场景）
4. 最后总结升华（主题/体验）

**并行可能性**: 
- L03 和 L04 可并行（人物系统整体分析）
- L05 和 L06 可并行（形式分析）
- L07 和 L08 可并行（艺术分析）

## 4. 输出规范

### 4.1 JSON Schema 要求

每层输出必须符合以下基本结构：

```json
{
  "layer": "string (枚举值)",
  "book_title": "string",
  "analysis": { /* 层特定内容 */ },
  "evidence": ["string (至少3条)"],
  "imitation_rules": ["string (至少3条)"],
  "stability_assessment": {
    "score": "1-10",
    "reasoning": "string (必填)",
    "variation_points": ["string"]
  }
}
```

### 4.2 Evidence 质量标准

**高质量 evidence**：
- 包含具体的章节引用（如"第23章"）
- 包含原文摘录（关键句或段落）
- 说明该证据证明了什么

**低质量 example**（避免）：
- 模糊引用（如"书中经常出现..."）
- 无原文支持
- 与分析结论无明确关联

### 4.3 Imitation Rules 质量标准

**高质量的仿写规则**：
- 可操作（能直接指导写作）
- 具体（包含参数或检查清单）
- 有条件说明（何时使用/何时不使用）
- 有示例（正面/反面案例）

**低质量的仿写规则**（避免）：
- 过于抽象（如"要写得生动"）
- 无条件限制（万能规则通常无用）
- 无示例支撑

## 5. 仿写规则示例

### 示例1: 来自 Layer 01 (工程层)

**规则名称**: 章节长度节奏控制法则

```
【规则】"波浪式章节长度"模式
条件: 当你需要调控阅读节奏时
操作: 
  1. 铺垫章: 2000-3000字（轻快，快速读完）
  2. 标准章: 3000-5000字（正常节奏）
  3. 高潮章: 5000-8000字（沉浸，慢读）
  4. 缓冲章: 1500-2500字（极快，喘息）
模式: [铺垫]→[标准]×2-3→[高潮]→[缓冲]→循环
注意: 连续两个高潮章会导致疲劳
来源: 基于《{book_title}》的统计分析
稳定度: 高（全书85%的卷遵循此模式）
```

### 示例2: 来自 Layer 03 (主角层)

**规则名称**: 九维坐标一致性检验清单

```
【规则】人物行为前的一致性检查
时机: 每次让主角做出重要决定之前
检查项目:
  □ 这个决定是否符合道德坐标（__分）？
  □ 这个决定是否符合利己-利他坐标（__分）？
  □ 这个决定是否符合主动-被动坐标（__分）？

```

### 示例3: 来自 Layer 06 (语言层)

**规则名称**: 句长节奏配比公式

```
场景类型: 一般叙述段落
推荐配置:
  - 短句(<15字): 30-40%
  - 中句(15-30字): 40-50%
  - 长句(>30字): 10-20%
特殊调整:
  + 紧张场景: 短句+10%, 长句-10%

  ✗ 连续超过5个长句（导致阅读疲劳）
  ✗ 连续超过8个短句（导致碎片化）
```

## 6. 质量评估标准

### 6.1 单层分析质量评分卡

| 评分项 | 权重 | 评分标准 |
|--------|------|---------|
| 分析全面性 | 20% | 是否覆盖了该层所有关键维度？ |
| Evidence 质量 | 25% | 证据是否具体、充分、相关？ |
| 洞察深度 | 20% | 是否超越了表面观察？ |
| 仿写规则实用性 | 20% | 规则是否可操作、有价值？ |
| 稳定度判断准确性 | 15% | 对一致性的评估是否准确？ |

### 6.2 整体分析质量等级

| 等级 | 总分 | 特征 |
|------|------|------|
| S | 95-100 | 大师级分析，可直接用于创作指导 |
| A | 85-94 | 优秀分析，高度可用 |
| B | 74-84 | 良好分析，主要方面到位 |
| C | 60-73 | 合格分析，有明显遗漏或浅显 |
| D | <60 | 不合格，需要重新分析 |

### 6.3 常见质量问题

| 问题 | 表现 | 改进建议 |
|------|------|---------|
| 过于表面 | 只描述不分析 | 增加"为什么"和"如何"的追问 |
| 证据不足 | 泛泛而谈 | 强制要求每点至少2个原文例证 |
| 忽视矛盾 | 假设完全一致 | 主动寻找不一致之处并解释 |
| 规则空洞 | 无法执行 | 要求规则必须包含具体参数 |
| 缺乏双视角 | 只有技术或只有文学 | 强制同时提供两侧分析 |
