# 自然对话交互模式指南

## 核心原则：两阶段响应模式

本技能的所有交互都遵循 **两阶段响应** 原则：

```
用户请求 → [阶段A] CLI执行（建骨架）→ [阶段B] AI填充（填内容）→ 完成
```

**关键规则**：
- 阶段A完成后，**必须明确告知用户/AI**："模板已创建，接下来需要填充内容"
- 如果当前环境有 AI 能力，**自动进入阶段B**
- 绝不能让用户误以为 CLI 输出就是最终结果

## 填充状态检查命令

当不确定哪些文件已填充、哪些还是空模板时，可以使用以下方式检查：

### 方法1：搜索占位符

```bash
# 检查某文件是否还有未填充的占位符
grep -c "\[待" plan/05-情节规划/全书大纲.md
# 返回 0 = 已填充，返回 >0 = 还有占位符
```

### 方法2：查看文件大小

```bash
# 空模板通常 < 1KB，已填充的 > 3KB
ls -la plan/06-阶段规划/章节蓝图/*.md
```

### 方法3：询问 Skill

```
用户：哪些文件还没填充？
Skill：[扫描所有 .md 文件，列出含 [待 的文件清单]
```

## 批量填充模式

对于大型项目（如750章），逐个填充不现实。支持批量模式：

### 用户输入：
> 把剩下的全填充了 / 批量填充阶段2-7的大纲和蓝图

### Skill 响应：

```
收到，进入批量填充模式。

本次批量填充范围：
📋 阶段概要：第2-7阶段（6个文件）
📋 章节蓝图：第11-750章（740个文件）

由于数量较大，我将分批进行：

批次1：填充 6 个阶段概要（预计耗时较长）
  进程：▓▓▓▓▓░░░░░ 50%

批次2：填充 第11-50章蓝图（40章）
批次3：填充 第51-100章蓝图（50章）
...（以此类推）

⚠️ 批量填充的质量可能低于逐个精细填充。
   如对某部分质量不满意，可以后续单独重新填充。

是否开始批量填充？
```

### 新增：填充相关关键词

| 用户关键词 | 动作 | 说明 |
|-----------|------|------|
| 填充/补全/完善 | 进入阶段B | 对已有模板填充内容 |

## 错误恢复策略（补充）

### 错误4：尝试写作但蓝图未填充

```
❌ 第5章蓝图是空模板，无法获取有效上下文

原因：blueprint generate 只创建了模板，尚未填充内容

解决方案（按顺序尝试）：
1. 填充第5章蓝图：读取阶段概要 → 填充第005章蓝图.md
2. 或跳过第5章，先写其他已填充的章节
3. 或批量填充第1-10章蓝图后重试
```

### 错误5：大纲依赖缺失

```
⚠️ 无法填充阶段概要：大纲尚未填充

填充顺序必须是：大纲 → 阶段概要 → 章节蓝图

请先执行：填充 plan/05-情节规划/全书大纲.md
```

## 最佳实践（更新）

1. **⚠️ 永远不要让 CLI 输出看起来像最终结果** — 模板必须明确标记
2. **每次 CLI 命令后立即说明下一步** — 不要等用户问
3. **大项目用批量模式** — 750章不可能逐个填充
4. **填充前检查上级依赖** — 蓝图依赖阶段概要，阶段概要依赖大纲
5. **定期汇报填充进度** — 让用户知道完成了多少/还剩多少
6. **允许选择性重填** — 用户可能对某章不满意要求重新来过
