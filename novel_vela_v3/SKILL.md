## 核心架构：两阶段协作模型

```
┌─────────────────────────────────────────────────────┐
│  阶段1：CLI 工具层（novel_cli.py）                   │
│  职责：建骨架、管数据、出模板、RAG检索、审查同步      │
│  输出：目录结构 + SQLite库 + Markdown空模板           │
└──────────────────────┬──────────────────────────────┘
                       │ 模板文件就位后
                       ▼
┌─────────────────────────────────────────────────────┐
│  阶段2：AI 内容层（Claude/其他AI代理）               │
│  职责：读模板、填内容、生成具体创作物                 │
│  输入：小说信息.md + 文风参考 + 设计文档 + 模板       │
│  输出：填充完整的大纲/蓝图/正文                       │
└─────────────────────────────────────────────────────┘
```

**关键原则**：
- CLI 命令中的 `generate` = **生成模板文件**（含占位符），不是生成最终内容
- 最终内容必须由 **AI 读取模板后填充**
- 两阶段必须按顺序执行：先 CLI 建骨架 → 再 AI 填内容

## CLI 命令速查表

| 命令 | 阶段 | CLI 输出 | AI 后续动作 | 优先级 |
|------|------|---------|------------|--------|
| `init` | 1 | 项目目录+DB+基础信息.md | 生成文风参考文档 | 🟢 |
| `outline create` | 1 | 全书大纲.md（**空模板**） | 🔴 **必须填充**：故事梗概+分阶段剧情+人物弧线 | 🔴 |
| `stage add` | 1 | 阶段概要.md（**空模板**）+ DB记录 | 🟡 **建议填充**：剧情概要+目标+爽点 | 🟡 |
| `blueprint init` | 1 | 第XXX章蓝图.md（**空模板**）+ DB记录 | 🔴 **必须填充**：目标+场景+伏笔+爽点 | 🔴 |
| `character add` | 1 | 仅 DB记录 | 🟢 可选：创建人物详细设定md | 🟢 |
| `context get` | 2 | 实时上下文报告（无需填充） | 直接用于写作参考 | - |
| `write` | 2 | 写作准备提示 | AI 执行实际写作 | - |
| `rag search` | 2 | 语义搜索结果（需Ollama） | 直接用于参考 | - |
| `audit chapter` | 2 | 单章/批量审查报告 | 根据报告修正 | - |
| `sync db-to-md` | 2 | DB数据同步到Markdown | 检查一致性 | - |

> 🔴 = 必须由 AI 填充才能继续下一步 | 🟡 = 建议填充 | 🟢 = 可选

## 核心功能模块

### 1. 数据库管理（NovelDB）

封装所有数据库操作，支持上下文管理器。

**核心表（11张）**：
- `novels` / `stages` / `characters` / `maps` / `chapters` / `foreshadowing`
- `character_relations` / `character_appearances` / `chapter_scenes` / `versions` / `rag_chunks`

### 2. RAG向量检索（RAGRetriever）✅ V1功能恢复

**技术栈**：sqlite-vec + Ollama (nomic-embed-text, 768维)

**完整功能**：
- `add_chunk()` - 添加文本切片并生成向量嵌入
- `search()` - 语义搜索（余弦相似度排序）
- `rebuild_index()` - 重建向量索引
- `get_status()` - 查看索引状态

**使用前提**：
- 安装 Ollama 并运行本地服务
- 拉取嵌入模型：`ollama pull nomic-embed-text`
- 安装 Python 依赖：`pip install sqlite-vec requests`

### 3. 上下文管理（ContextManager）✅ V1功能恢复

**动态上下文窗口**：
- 优先最近3章
- 累计字数不超过10000字
- 最多5章

**输出内容**：
1. 本章蓝图（从蓝图文件读取）
2. 前文摘要（动态计算）
3. 活跃人物状态（排除已死亡，按重要度排序）
4. 待回收伏笔（status='planted'）
5. 当前地图信息
6. RAG召回设定（可选，需Ollama）
7. 文风提示（从参考文档读取）

### 4. 审查与同步（audit/sync）✅ V1功能恢复

**audit chapter** - 单章审查：
- 检查蓝图完整性
- 检查人物一致性
- 检查伏笔呼应
- 检查战力体系合理性

**audit range** - 批量审查（指定章节范围）

**sync db-to-md** - DB数据同步到Markdown：
- 人物数据 → `plan/03-角色设定/人物总览.md`
- 章节状态 → `plan/06-阶段规划/章节状态.md`

**sync check** - 一致性检查：
- DB vs Markdown 数据对比
- 报告差异项

## 去AI味策略

三层防护机制：

1. **Prompt约束**（写作提示词中）
2. **文风学习**（初始化时）→ 存入 `plan/02-核心设定/参考作品与文风.md`
3. **后处理修正**（写作后）

详见 [references/style-analysis-template.md](references/style-analysis-template.md)

## 交互模式

支持自然语言对话式交互，详见 [references/interaction-patterns.md](references/interaction-patterns.md)

**关键交互规则**：

当用户说"生成大纲"/"创建蓝图"时：
1. 先执行对应的 CLI 命令（创建模板）
2. **然后立即提醒用户/AI**："模板已创建，需要填充内容"
3. 如果当前环境有 AI 能力，**自动进入填充流程**

## 注意事项

1. **Python路径**：必须使用 `C:\Python\Python313\python.exe`
2. **依赖安装**：`C:\Python\Python313\python.exe -m pip install click requests sqlite-vec`
3. **路径处理**：CLI自动识别三种路径模式（直接plan/novel.db、《书名》目录、子目录搜索）
4. **蓝图纸置**：统一存放在 `06-阶段规划/章节蓝图/` 目录
5. **模版数据库**：位于 `assets/templates/novel_template.db`
6. **⚠️ 最重要**：`outline create` / `blueprint init` / `stage add` 只创建**空模板**，必须由 AI 填充实际内容
7. **RAG前提**：需要 Ollama 服务运行，否则 rag search 会提示未安装
