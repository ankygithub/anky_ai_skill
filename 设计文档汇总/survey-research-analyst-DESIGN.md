# survey-research-analyst 技能设计文档

> 专业调研分析报告生成技能 —— 支持 6 大调研类型，输出带导航栏、主题切换、响应式布局的交互式 HTML 报告。

---

## 一、概述

### 1.1 技能定位

`survey-research-analyst` 是一个专业调研分析报告生成工具。它支持 6 大调研类型（市场调研、竞品分析、用户研究、行业趋势、技术调研、政策解读），采用 MD-first 架构（Markdown 文档优先），最终输出为带有导航栏、主题切换、响应式布局的专业交互式 HTML 报告。

核心理念：**用工程化的写作流程保证调研报告的质量和一致性**。

### 1.2 核心价值

传统调研报告写作面临的问题：
- **结构混乱**：缺乏标准化的章节框架
- **来源不透明**：数据来源不清，可信度无法评估
- **格式不统一**：每次报告格式不一致
- **信息难追踪**：写作过程中收集的原始资料无处存放

本技能通过框架文档驱动 + 信源分级 + 搜索预算控制 + 标准化输出模板，解决这些问题。

### 1.3 支持的调研类型

| 类型 | 英文名 | 适用场景 |
|------|--------|----------|
| 市场调研 | market | 市场规模、竞争格局、进入策略 |
| 竞品分析 | competitor | 产品对比、优劣势分析、差异化 |
| 用户研究 | user | 用户画像、需求分析、行为洞察 |
| 行业趋势 | industry | 技术趋势、市场走向、未来预测 |
| 技术调研 | technology | 技术选型、架构评估、可行性 |
| 政策解读 | policy | 政策分析、合规评估、影响研判 |

### 1.4 触发场景

- 需要生成结构化调研报告
- 市场分析、竞品对比
- 用户洞察、行业研究
- 技术评估、政策分析

## 二、架构设计

### 2.1 整体架构

采用**三波次（Wave）** 工作流架构：

```
┌──────────────────────────────────────────────────────┐
│  Wave 1：信息收集                                     │
│  - 核心问题拆解为 3-5 个子问题                         │
│  - 每子问题最多 3 轮搜索                               │
│  - 信源分级记录（A/B/C）                              │
├──────────────────────────────────────────────────────┤
│  Wave 2：分析写作                                     │
│  - 按顺序编辑 docs/ 目录下的 Markdown 文件             │
│  - 每个观点必须有数据支撑                              │
│  - 所有数据标注来源和等级                              │
├──────────────────────────────────────────────────────┤
│  Wave 3：深度分析                                     │
│  - 交叉验证关键数据                                    │
│  - 补充缺失信息                                       │
│  - 生成核心发现                                       │
└──────────────────────────────────────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────────────┐
│  构建与交付                                           │
│  - rebuild.sh 合并 Markdown → 应用样式 → 生成 HTML    │
│  - 支持 HTML / Markdown / Both 三种输出格式            │
└──────────────────────────────────────────────────────┘
```

## 三、核心模块

### 3.1 项目初始化模块 (init-project.sh)

**职责**：根据调研类型创建标准化的项目结构。

**使用方式**：
```bash
# 语法：bash init-project.sh -n <项目名> -t <报告类型>
bash scripts/init-project.sh -n "AI写作工具市场调研" -t "market"
bash scripts/init-project.sh -n "Notion竞品分析" -t "competitor"
bash scripts/init-project.sh -n "Z世代用户研究" -t "user"
```

**初始化行为**：
1. 创建项目目录结构（docs/, research/, sources/, output/）
2. 根据报告类型自动生成对应的章节 Markdown 文件
3. 生成 project-info.md 项目配置模板
4. 生成 sources/sources.md 来源清单模板
5. 复制 rebuild.sh 到项目目录

### 3.2 报告构建模块 (rebuild.sh)

**职责**：将 Markdown 章节合并为完整的 HTML 报告。

**支持的输出格式**：

| 格式 | 命令 | 输出文件 | 适用场景 |
|------|------|----------|----------|
| HTML | `bash rebuild.sh` | `{项目名称}_report.html` | 在线浏览、分享、打印 |
| Markdown | `bash rebuild.sh md` | `{项目名称}_report.md` | 导入其他系统、版本控制 |
| Both | `bash rebuild.sh both` | 同时生成两种格式 | 需要多种格式时 |

**构建流程**：
```
1. 读取 docs/ 目录下所有 .md 文件（按编号排序）
2. 合并为单文件报告
3. 应用 templates/styles.css 样式
4. 注入 HTML 模板（含导航栏、主题切换、字号调节等）
5. 输出到 output/ 目录
```

**构建脚本依赖**：
- Node.js（用于执行 build.js）
- templates/ 目录下的模板文件

**环境变量**：
```bash
# 如果 rebuild.sh 找不到 skill 目录
export SURVEY_SKILL_DIR=/path/to/skill-code/survey-research-analyst
bash rebuild.sh
```

### 3.3 框架文档系统

**职责**：为每种调研类型提供标准化的章节结构和分析框架。

**框架文档内容**：
- 该调研类型的标准章节结构
- 每个章节应包含的内容要点
- 推荐的分析框架和方法

**框架文档示例（market.md）**：
```markdown
# 市场调研框架

## 标准章节结构
1. 执行摘要
2. 市场规模与增长
3. 竞争格局分析
4. 用户需求与痛点
5. 市场机会识别
6. 进入策略建议
7. 风险评估
8. 结论与行动计划

## 分析方法
- TAM/SAM/SOM 模型
- 波特五力模型
- 用户画像分析
- SWOT 分析
```

### 3.4 信源分级系统

**职责**：确保所有数据可追溯、可验证。

**三级信源分类**：

| 等级 | 类型 | 示例 | 可信度 |
|------|------|------|--------|
| **A 级** | 官方/权威 | 政府官网、官方财报、权威期刊 | 高 |
| **B 级** | 权威媒体/智库 | 路透社、麦肯锡报告、Gartner | 中高 |
| **C 级** | 行业博客/论坛 | 技术博客、知乎、行业论坛 | 中（需验证） |

**信源记录格式**：
```markdown
## A 级来源（官方/权威）
- [来源名称](URL) - 用途说明 - 日期

## B 级来源（权威媒体/智库）
- [来源名称](URL) - 用途说明 - 日期

## C 级来源（行业博客/论坛）
- [来源名称](URL) - 用途说明 - 日期
```

### 3.5 HTML 报告模板

**职责**：生成专业的交互式 HTML 报告。

**报告特性**：
- **响应式布局**：支持桌面端和移动端
- **侧边栏目录**：自动生成的可点击目录导航
- **主题切换**：支持明/暗主题
- **字号调节**：小/中/大三档字号
- **内容宽度调节**：默认/宽/更宽/超宽/全屏五档
- **平滑滚动**：点击目录项平滑滚动到对应章节
- **目录高亮**：滚动时自动高亮当前章节

## 七、关键设计决策

### 7.1 MD-first 架构

**决策**：先写 Markdown 文档，再构建为 HTML 报告。

**原因**：
- Markdown 是纯文本，便于版本控制和协作编辑
- HTML 构建是可逆过程（HTML → Markdown 也可行）
- 支持多种输出格式（HTML/Markdown/PDF 等）
- 写作过程不受格式干扰，专注于内容

### 7.2 框架文档驱动

**决策**：每种调研类型有独立的框架文档。

**原因**：
- 确保报告结构标准化
- 降低写作门槛（按框架填空即可）
- 不同调研类型有不同的分析方法和章节结构
- 框架文档可独立更新，不影响现有项目

### 7.3 信源分级机制

**决策**：所有数据必须标注来源等级（A/B/C）。

**原因**：
- 提高报告的可信度透明度
- 读者可以自行判断数据的可靠性
- 促使写作者优先使用权威来源
- C 级来源需要验证，避免虚假信息

### 7.4 搜索预算控制

**决策**：严格限制搜索次数和时间。

**原因**：
- 防止搜索无限膨胀（陷入信息过载）
- 快速模式 30 分钟强制聚焦核心问题
- 标准模式 1-2 小时保证深度但不拖延
- 每子问题最多 3 轮搜索，避免过度深挖

### 7.5 三波次工作流

**决策**：将工作流拆分为信息收集 → 分析写作 → 深度分析三个波次。

**原因**：
- 避免边搜边写导致的思路混乱
- Wave 1 专注收集，Wave 2 专注写作，Wave 3 专注验证
- 每个波次有明确的输出物
- 支持不同人员分工协作

### 8.1 快速开始

```bash
# 1. 创建项目
bash scripts/init-project.sh -n "AI 写作工具市场调研" -t "market"

# 2. 进入项目目录
cd "AI 写作工具市场调研"

# 3. 编辑 project-info.md，填写调研目标和核心问题

# 4. 阅读框架文档
cat ../references/frameworks/market.md

# 5. 开始信息收集和写作（编辑 docs/ 下的 .md 文件）

bash rebuild.sh

start output/AI写作工具市场调研_report.html
```
