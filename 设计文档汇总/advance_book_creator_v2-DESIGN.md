# advance_book_creator_v2 设计文档

## 概述

`advance_book_creator_v2` 是 `advance_book_creator`（v4架构）的增强版本，同样采用 **MD-first（Markdown优先）架构**。在保留v1全部功能的基础上，新增了**防幻觉强制规则**和**组件使用强制规范**，从源头上确保生成内容的准确性和视觉质量。

核心定位：在v1基础上强化内容质量控制，适用于对内容准确性要求更高的场景。

## 核心模块

### 1. 防幻觉强制规则模块（v2新增）

写作阶段必须遵守的5条强制规则：

```markdown
规则1：强制搜索验证
  所有涉及具体数据、版本号、参数配置、API接口、事实陈述的内容，
  必须调用WebSearch工具验证，禁止直接输出未验证的大模型内部知识

规则2：强制信源标注
  正文引用的所有外部事实，必须在引用处或章节末尾标注信源来源
  格式：（来源：官方文档/论文URL，获取时间：202X-XX-XX）

规则3：强制时效检查
  技术类内容涉及版本、特性时，必须标注该信息的时效性
  如："截至2025年1月"，过期内容自动标记⚠️

规则4：强制矛盾处理
  同一主题存在多个信源且内容矛盾时，必须并列呈现各方观点
  标注争议点，禁止单方面采信

规则5：强制高风险确认
  涉及安全、法律、医疗、金融等高风险领域的内容，
  写作完成后必须提示用户确认关键事实，未经确认不得写入正文
```

### 2. 场景-组件映射模块（v2新增）

将写作场景与HTML组件建立强制映射关系：

| 场景 | 必须使用的组件 | 触发条件 | 最低用量 |
|------|--------------|---------|---------|
| 章节核心要点、关键结论 | `callout-tip` | 每个Part至少≥1个 | 1个/Part |
| 安全警告、注意事项 | `callout-warn` | 出现"危险/禁止/不要/风险/⚠️" | 按需 |
| 参考信息、数据来源 | `callout-info` | 出现"参考/来源/延伸/详情" | 按需 |
| 2步以上操作步骤 | `step` | 有序操作必须使用 | 按需 |
| 好坏对比、方案选型 | `compare` | 有对比内容必须使用 | 按需 |
| 关键术语首次出现 | `tag-core` | 专业术语建议使用 | 建议 |
| 多分支决策逻辑 | `flow` | 决策树建议使用 | 建议 |

**每个Part的最低用量底线：**
- 至少 **1个** callout组件（tip/warn/info任选）
- 包含操作步骤 → 必须用step组件
- 包含对比内容 → 必须用compare组件
- 禁止整个Part零组件（纯文本输出）

### 3. 标签闭合检测与降级保护模块（v2新增）

```
输入：fragments/*.md（含内嵌HTML组件）
  ↓
convert-md.js 检测标签闭合状态
  ↓
  ├── 标签完整闭合 → 正常转换为HTML片段
  ├── 简单缺失闭合标签 → 自动补全
  └── 复杂结构损坏 → 降级为纯文本块（保留文字，丢失样式）
  ↓
输出：output/convert-md-fix-report.txt（降级报告）
```

**常见错误示例：**
```html
<!-- ❌ 错误：标签未闭合 -->
<div class="callout callout-tip">
  <p>内容
</div>

<!-- ❌ 错误：嵌套顺序错误 -->
<div><span></div></span>

<!-- ❌ 错误：自闭合标签写错 -->
<br  <!-- 应为 <br/> -->

<!-- ❌ 错误：标签名拼写错误 -->
<dvi>内容</dv>
```

### 4. 版本管理模块（继承v1）

基于语义化版本（SemVer）：
```bash
./update.sh patch "修正错误"    # 1.0.0 → 1.0.1
./update.sh minor "更新内容"    # 1.0.0 → 1.1.0
./update.sh major "新增章节"    # 1.0.0 → 2.0.0
```

### 5. 构建模块（继承v1）

构建脚本体系与v1完全一致：

| 脚本 | 功能 |
|------|------|
| `convert-md.js` | Markdown → HTML片段（含v2增强检测） |
| `convert-html.js` | HTML → HTML片段（兼容模式） |
| `build-all.js` | 统一构建入口 + MD预处理 + 产物门禁 |
| `build.js` | 单文件HTML构建 |
| `build-pdf.js` | PDF生成（两遍渲染精确书签） |
| `build-md.js` | Markdown导出 |
| `build-reader.js` | 多文件阅读器构建 |
| `update.sh` | 版本更新+构建 |

## 工作流程

### 完整工作流（模式A）

```
1. 初始化项目 ──→ bash init-project.sh <目录> <标题>
2. 调研         ──→ 多Agent并行调研 → research/*.md
                  （强制WebSearch验证 + 信源标注）
3. 规划         ──→ 编辑 PROJECT.md → 用户确认大纲
4. 写作         ──→ 多Agent并行输出 fragments/*.md
                  （v2增强：防幻觉验证 + 组件强制使用 + 标签检查）
5. 构建         ──→ node build-all.js --products all
                  （v2增强：convert-md-fix-report.txt 生成）
6. 版本更新     ──→ ./update.sh <patch|minor|major>
```

### 信息获取策略

| 场景 | 推荐方式 | 说明 |
|------|---------|------|
| 调研阶段收集背景知识 | Task(search) sub_agent | 用 SearchCodebase + Grep + Glob + Read 组合搜索 |
| 写作时需要查具体数据/事实 | WebSearch 工具（单次） | 直接调用，不走 skill 嵌套 |
| 需要抓取网页内容解析 | WebFetch 工具 | 抓取 URL 内容转为 markdown |
| 禁止 | multi-search-engine skill | 嵌套调用容易卡死 |

## 关键设计决策

### 1. 防幻觉机制的系统性设计

**决策**：在v1基础上引入5条强制性防幻觉规则，贯穿写作全流程。

**理由**：
- AI生成内容存在"幻觉"风险，可能输出不准确的事实
- 单纯依赖AI内部知识不可靠，必须强制外部验证
- 通过系统性规则降低内容错误率

**实施策略**：
- 规则1-2在调研阶段即开始执行（搜索+标注）
- 规则3-5在写作阶段执行（时效+矛盾+高风险）
- 所有规则在Agent prompt中强制要求

### 2. 场景-组件映射的强制化

**决策**：将组件使用从"建议"升级为"强制"，建立场景-组件映射表。

**理由**：
- v1中Agent可能忽略组件使用，导致产物缺乏视觉层次
- 强制映射确保每个Part都有足够的视觉组件
- 最低用量底线保证整体质量

**权衡**：增加了Agent的复杂度，但显著提升了产物质量。

### 3. 降级保护机制

**决策**：标签结构损坏时自动降级为纯文本块，而非直接失败。

**理由**：
- 保留内容完整性（至少文字不丢失）
- 生成降级报告便于后续修复
- 比直接报错更友好

### 4. 兼容v1架构

**决策**：v2保持与v1相同的项目结构、构建脚本和产物格式。

**理由**：
- 降低迁移成本
- 用户可以按需升级到v2
- 保持生态一致性

## 使用说明

```bash
npm install playwright pdf-lib
```

### 快速开始

```bash

# 2. 编辑PROJECT.md，规划大纲

# 5. 检查降级报告（如果有）
#    查看 output/convert-md-fix-report.txt
```

### v2写作模板示例

```markdown
---
type: chapter
title: 第一章 章节标题
---

## 第一章 章节标题

### 1.1 小节标题

正文内容，使用 **粗体**、*斜体*、`行内代码` 等 Markdown 语法。

<!-- ✅ 必须：每个Part至少1个callout -->
<div class="callout callout-tip">
<div class="callout-title">核心要点</div>
<p>本章最重要的3个结论：...</p>
</div>

<!-- ✅ 对比时必须用compare组件 -->
<div class="compare">
<div><p><strong>不推荐 ❌</strong></p><p>不好做法</p></div>
<div><p><strong>推荐 ✅</strong></p><p>好做法</p></div>
</div>

<!-- ✅ 操作步骤必须用step组件 -->
<div class="step">
<div class="step-num">1</div>
<div class="step-content"><h4>步骤标题</h4><p>步骤说明</p></div>
</div>

<!-- ✅ 关键术语使用tag -->
<span class="tag-core">重要术语</span>

（来源：https://docs.example.com，获取时间：2026-05-23）
```
