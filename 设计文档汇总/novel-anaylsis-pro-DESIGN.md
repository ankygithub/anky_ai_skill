# novel-analysis-pro 技能设计文档

> 网文作者风格解析技能 —— 通过分层抽样 + 统计分析 + LLM深读，生成结构化的风格指纹报告。

---

## 一、概述

### 1.1 技能定位

`novel-analysis-pro` 是一个面向网文创作领域的风格解析工具。它读取指定文件夹下同一作者的 TXT 作品合集，通过分层抽样、统计分析与 LLM 深度阅读相结合的双视角方法，输出三份产物：

- **完整分析报告**（Markdown）：供人阅读的深度风格分析
- **AI 风格速查卡**（压缩版 system prompt）：供 AI 仿写时调用
- **场景模板库与写作检查清单**：供写作时实时参考

### 1.2 核心价值

传统风格分析往往停留在表面特征（如"用词华丽"），而本技能独创**十层技术分析框架 + 六维文学感知**的双视角融合方法：

- **技术侧**：可量化指标 + 操作规则（给 AI 的"操作手册"）
- **文学侧**：氛围画像 + 情绪纹理 + 美学定位（给 AI 的"审美指南"）

最终合并为融合版写作指令，避免 AI 生成内容的机械感。

### 1.3 触发场景

用户要求以下操作时使用本技能：
- "分析某作者的写作风格"
- "提取小说作家风格指纹"
- "生成风格仿写指南"
- "分析网文作者特色"

## 二、架构设计

### 2.1 整体架构

采用**五阶段流水线**架构，各阶段职责清晰、可独立测试：

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  文本预处理  │───▶│  统计层分析  │───▶│ 分层抽样+   │───▶│  交叉验证    │───▶│  报告生成    │
│  (Task2)    │    │  (Task4)    │    │  LLM深读     │    │  (Task6)    │    │  (Task7)    │
│  Token: 0   │    │  Token: 0   │    │  (Task5)    │    │  Token: 0   │    │  Token: 0   │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
                                          │
                                   Token成本高
                               （仅此阶段调用LLM）
```

### 2.2 阶段说明

| 阶段 | 模块 | 输入 | 输出 | Token成本 |
|------|------|------|------|-----------|
| 1. 文本预处理 | `text_preprocessor.py` | 原始 TXT 文件 | 清洗后的章节集合 | 0 |
| 2. 统计层 | `stat_analyzer.py` | 清洗文本 | 句长/词频/对话比等统计指标 | 0 |
| 3. 分层抽样 | `sampler.py` | 全书章节 | 四类切片（开篇/高潮/日常/收尾） | 0 |
| 4. LLM 深读 | `llm_analyzer.py` | 采样文本 + 提示词 | 十层 + 六维分析结果 | 高 |
| 5. 交叉验证 | `cross_validator.py` | 多书分析结果 | 标注稳定度 (H/M/L) | 0 |
| 6. 报告生成 | `report_generator.py` | 全部分析数据 | 五份产物文件 | 0 |

## 三、核心模块

### 3.1 文本预处理模块 (text_preprocessor.py)

**职责**：将原始 TXT 文件转化为标准化的章节数据结构。

**核心功能**：
- **编码检测**：自动识别 GBK/UTF-8 等编码格式
- **广告清洗**：移除常见的网文广告水印
- **章节切分**：基于正则表达式自动识别章节边界

```python
# 章节切分正则示例
CHAPTER_PATTERN = r'^第[零一二三四五六七八九十百千万\d]+章\s+.+$'
```

**数据模型**：
```python
class Chapter:
    number: int           # 章节序号
    title: str            # 章节标题
    content: str          # 正文内容
    word_count: int       # 字数
    book_id: str          # 所属书籍ID
```

### 3.2 统计分析模块 (stat_analyzer.py)

**职责**：对全文本进行纯代码层面的量化统计，不依赖 LLM。

**统计维度**：
| 维度 | 指标 | 用途 |
|------|------|------|
| 句长分析 | 均值/中位数/标准差/分布类型 | 判断语言节奏 |
| 词频统计 | TOP50 实词、特殊词汇 | 提取词汇偏好 |
| 对话比例 | 对话行数/总行数 | 判断叙事风格 |
| 标点密度 | 逗号/叹号/省略号占比 | 情绪表达倾向 |
| 段落长度 | 均值/分布 | 排版习惯 |

### 3.3 分层抽样模块 (sampler.py)

**职责**：从百万字作品中智能采样 15-20 章（约 5 万字），供 LLM 深读。

**四类采样策略**：

| 类型 | 取法 | 分析重点 | 算法依据 |
|------|------|---------|----------|
| **开篇** | 固定前 5 章 | 设定铺设、主角人设、基调 | 位置固定 |
| **高潮** | 算法识别 TOP5 | 多指标综合打分 | 情绪词密度 + 标题关键词 + 段落长度 + 字数突变 |
| **日常** | 反选逻辑 TOP5 | 低情绪词密度 + 高生活词密度 | 反向高潮算法 |
| **收尾** | 固定最后 3 章 | 结局处理、收束节奏 | 位置固定 |

**跨书对齐**：按百分比位置对齐采样点，确保不同长度作品的可比性。

### 3.4 LLM 分析模块 (llm_analyzer.py)

**职责**：对采样文本执行十层技术分析 + 六维文学感知。

**执行流程**：
```
采样文本 ──▶ 加载对应 prompt ──▶ 调用 LLM API ──▶ 解析结构化输出 ──▶ 返回分析结果
```

**十层技术分析框架**：

| 层级 | 名称 | 核心内容 | 优先级 |
|------|------|---------|--------|
| L1 | 作品工程层 | 章节结构、长度、钩子、标题风格 | 必做 |
| L2 | 情节结构层 | 爽点模式、冲突设计、反转机制 | 必做 |
| L3 | 主角伦理与行动哲学层 | 九维坐标、决策模式、底线系统 | 必做 |
| L4 | 人物关系与群像层 | 配角原型、反派塑造、感情线 | 应做 |
| L5 | 叙事视角与信息控制层 | POV、信息差、旁白风格 | 应做 |
| L6 | 语言风格层 | 句长、词汇、句式、声音画像 | 必做 |
| L7 | 修辞文化层 | 典故、诗词、命名系统 | 选做 |
| L8 | 场景类型层 | 战斗/日常/对话/抒情配方 | 应做 |
| L9 | 主题母题与价值观层 | 高频主题、信念体系 | 选做 |
| L10 | 读者体验层 | 爽点分布、情绪波形图 | 应做 |

**六维文学感知**：

| 维度 | 核心问题 | 输出 |
|------|---------|------|
| 情绪波形图 | 情绪如何波动？ | 波形图 + 质感分类 |
| 氛围配方集 | 氛围如何营造？ | 配方表 + 参数 |
| 人味指数 | 有没有生命感？ | 量化指数 + 分级 |
| 悲悼美学 | 悲伤如何升华为美？ | 类型学 + 升华路径 |
| 节奏呼吸感 | 律动是否自然？ | 乐谱式分析 |
| 作者签名 | 指纹是什么？ | 特征提取 + 画像 |

### 3.5 交叉验证模块 (cross_validator.py)

**职责**：对同一作者的多部作品进行跨书对比，标注特征的稳定度。

**稳定度分级**：
- **High (H)**：三部以上作品均出现，一致性 > 80%
- **Medium (M)**：部分作品出现，一致性 50-80%
- **Low (L)**：仅个别作品出现，可能是偶然特征

### 3.6 报告生成模块 (report_generator.py)

**职责**：将分析结果格式化为五份产物。

**输出产物清单**：

| 产物 | 文件名模式 | 用途 | 读者 |
|------|-----------|------|------|
| 完整报告 | `{作者}_风格分析报告_{时间}.md` | 深度风格解析 | 人 |
| AI 速查卡 | `{作者}_AI风格速查卡_{时间}.md` | 仿写 system prompt | AI |
| 场景模板库 | `{作者}_场景模板库_{时间}.md` | 写作场景配方 | AI/人 |
| 写作检查清单 | `{作者}_写作检查清单_{时间}.md` | 自检对照表 | 人 |
| 结构化数据 | `{作者}_风格数据_{时间}.json` | Agent 程序调用 | 机器 |

| `--intensity high` | L1-L10 + 六维文学感知 | 高 | 深度仿写学习 |

### 6.1 数据流图


## 七、关键设计决策

### 7.1 双视角融合设计

**决策**：每个分析层同时产出技术侧和文学侧输出。

**原因**：
- 纯技术分析容易忽略审美质感（如"句子短但节奏好"）
- 纯文学分析缺乏可操作性（如"写得很有味道"无法指导 AI）
- 双视角融合确保仿写指南既精准又有温度

**实现方式**：
- 技术侧：量化数据、结构模式、可复现原则、参数化描述
- 文学侧：审美效果、读者心理、艺术独特性、感性评价

### 7.2 分层抽样而非全量分析

**决策**：从百万字中采样约 5 万字供 LLM 阅读。

**原因**：
- LLM 上下文窗口有限（128K tokens 约 10 万字）
- 全量分析 Token 成本过高（百万字约 50-100 美元）
- 分层抽样算法确保覆盖关键场景（开篇/高潮/日常/收尾）
- 统计层仍对全量文本执行，保证数据完整性

### 7.3 零 Token 阶段优先

**决策**：文本预处理、统计分析、抽样、交叉验证、报告生成全部纯代码执行，Token 成本为零。

**原因**：
- 降低使用门槛，支持 `--stat-only` 快速模式
- 统计指标可作为 LLM 分析的参考数据
- 提高可测试性（纯函数易于单元测试）

### 7.4 稳定度标注机制

**决策**：对每个分析特征标注稳定度 (H/M/L)。

**原因**：
- 区分"作者一贯风格"与"偶然特征"
- 仿写时优先使用高稳定度特征
- 为多书作者提供更可靠的学习依据

## 八、使用说明

### 8.1 基础用法

```bash
# 分析某个作者的 txt 作品集
python scripts/analyze.py --input-dir "D:/path/to/author_books" --output-dir "./output"

# 完整用法（含文学感知维度）
python scripts/analyze.py --input-dir "D:/path/to/author_books" --model gpt-4o --intensity high

# 仅统计层分析（不调用 LLM，快速预览）
python scripts/analyze.py --input-dir "D:/path/to/author_books" --stat-only
```

### 8.2 CLI 参数速查

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--input-dir` | 输入文件夹路径（含 txt 作品集） | 必填 |
| `--output-dir` | 输出目录 | `./output` |
| `--model` | LLM 模型名称 | `gpt-4o` |
| `--intensity` | 分析强度 (low/medium/high) | `medium` |
| `--no-literary` | 禁用文学感知维度 | 启用 |
| `--stat-only` | 仅执行统计层分析 | 关闭 |
| `--json` | 额外输出 JSON 结构化数据 | 关闭 |

### 8.3 输入要求

- 文件夹内需包含同一作者的多部 TXT 格式小说
- 每部小说为独立 TXT 文件
- 章节需有标准格式（如"第一章 xxx"）
- 建议至少 2-3 部作品以获得可靠的跨书验证

### 8.4 输出示例
