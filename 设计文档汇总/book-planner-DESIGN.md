# book-planner 设计文档

## 概述

`book-planner` 是一个书籍大纲规划技能，核心职责是将用户输入的主题转化为完整的可执行书籍规划文档（PROJECT.md + 调研报告）。它不生成书籍正文内容，而是为后续的写书技能（如 `huashu-book-pdf2.1`、`advance_book_creator`）提供执行蓝图。

本技能通过4个阶段的系统化流程——意图澄清、深度调研、大纲规划、用户确认——确保输出的规划文档具备完整性、可执行性和高质量。

## 核心模块

### 1. 意图澄清与类型识别模块

**信息收集：**

| 信息项 | 是否必需 | 默认值 | 说明 |
|--------|---------|--------|------|
| 主题 | ✅ 必需 | - | 用户提供的书籍主题 |
| 目标读者 | 可选 | 可推断 | 目标读者群体 |
| 内容深度 | 可选 | L2 | L1入门 → L4专家 |
| 篇幅预期 | 可选 | 中等 | 短篇/中等/长篇 |
| 风格偏好 | 可选 | 混合 | 技术/故事/混合等 |
| 特殊素材路径 | 可选 | - | 用户上传的材料 |

**14类书籍类型识别：**

| 代号 | 名称 | 触发特征 |
|------|------|----------|
| T01 | 新技术学习类 | 技术术语/框架/平台 |
| T02 | K12学习辅导类 | 试卷/错题/薄弱点 |
| T03 | 应试备考指南类 | 考试名+备考/复习 |
| T04 | 科普知识类 | 科学概念/自然现象 |
| T05 | 历史深度解读类 | 历史事件/人物/朝代 |
| T06 | 商业案例分析类 | 公司+商业/案例/战略 |
| T07 | 个人成长方法论类 | 效率/习惯/思维/自我提升 |
| T08 | 产品工具手册类 | 软件/工具+教程/手册 |
| T09 | 地方文化旅行指南类 | 地名+旅行/文化 |
| T10 | 文学写作类 | 小说/散文/诗歌/创作 |
| T11 | 亲子教育类 | 家庭教育/儿童心理 |
| T12 | 职业技能成长类 | 职业路径/岗位能力 |
| T13 | 生活实用指南类 | 健康/理财/饮食/运动 |
| T14 | 综合型专题书 | 跨多类型复杂主题 |

**输出：** `analysis/pre-analysis.md`

```markdown
# 初始分析卡
## 书籍类型：[自动判定]
## 判定依据：[特征]
## 目标读者画像：[...]
## 内容深度：L1/L2/L3/L4
## 风格基调：[...]
## 核心主题清单：[3-5个]
## 调研维度列表：[N个]
## 预估篇幅：[X万字/X章]
## 特别注意事项：[...]
```

### 2. 深度调研模块

**步骤 1.1：加载调研模板**

根据阶段0识别的书籍类型，读取对应的调研维度模板：
- 读取 `references/research-templates/T{编号}-{类型}.md`
- 每个模板包含 8-10 个调研维度
- 跨类型时组合多套模板，去除重复维度

**步骤 1.2：生成搜索关键词**

每个调研维度自动生成 3-5 组关键词，覆盖：
- 中文核心词 + 英文专业词 + site限定词
- 示例：`"K8s 性能优化 最佳实践 2025 2026"` + `"Kubernetes performance benchmark"`

**步骤 1.3：执行网络搜索**

- 至少使用 2 个搜索引擎
- 技术类优先近12个月资料
- 一手信源优先（官方文档/论文/GitHub）
- 矛盾说法并列标注

**步骤 1.4：写入调研报告**

按标准格式保存至 `research/YYYY-MM-DD-{维度}.md`，包含可信度分级：

| 等级 | 类型 | 使用方式 |
|------|------|---------|
| A | 官方文档/论文/标准 | 核心依据 |
| B | 专家博客/技术大会 | 重要参考 |
| C | 社区讨论/问答 | 案例补充 |
| D | 未验证观点 | 仅线索 |

**步骤 1.5：交叉验证**

所有维度完成后输出 `research/cross-check.md`，检查：
- 矛盾点
- 依赖遗漏
- 单一信源
- 覆盖缺口

**步骤 1.6：调研汇总**

输出 `research/research-synthesis.md`，包含：
- 读者画像
- 核心问题地图
- 知识结构地图
- 证据矩阵
- 章节候选池
- 进入规划条件检查清单

### 3. 大纲规划模块

**生成 PROJECT.md，包含以下所有模块：**

| 模块 | 内容 |
|------|------|
| 项目元信息 | 标题、作者、版本、日期 |
| 书籍定位 | 是什么、不是什么、读完后的变化 |
| 读者画像 | 目标读者特征、痛点、期望 |
| 内容策略 | 深度、风格、写作原则 |
| 章节大纲表 | Part/节号/标题/核心内容/读者收益/信息来源/类型标签/前置依赖 |
| 知识递进路线 | 章节间的知识依赖关系 |
| 读者问题地图 | 读者可能遇到的问题及对应章节 |
| 证据矩阵 | 每个章节的支撑证据 |
| Agent并行分工方案 | 关联性强的Part分给同一个Agent |
| 调研资料索引 | 所有调研资料的路径和摘要 |
| 术语表 | 专业术语定义 |
| 图表与组件规划 | 优先SVG格式，标注"建议SVG"或"建议ASCII" |
| 风险清单 | 内容风险、技术风险、进度风险 |
| 进度追踪表 | 章节状态跟踪 |
| 用户确认区 | 用户确认记录 |
| 附录：调研资料索引 | 参考资料存档在附录，不跳转外部文件 |

**单章 Mini-Plan：**

```
### Chapter X: 标题
- 核心论点（≤30字）
- 读者读完能做什么
- 关键案例/数据
- 引用调研文件
- 与前章衔接/后章铺垫
- 预估字数/风险点
```

### 4. 质量自检模块

读取 `references/quality-checklist.md` 逐项检查，未通过则先修正再输出给用户。

### 5. 网络搜索策略模块

按书籍类型采用不同的搜索策略：

| 类型 | 优先目标 | 时效要求 |
|------|---------|---------|
| T01 新技术 | 官方文档/GitHub/技术博客 | 近12月 |
| T02 K12 | 课标官网/教材/真题库 | 近3年 |
| T03 应试 | 考试院/大纲/真题 | 最新 |
| T04 科普 | 学术期刊/科研机构 | 近5年 |
| T05 历史 | 史料库/学术论文 | 注意最新研究 |
| T06 商业 | 财报/新闻/行业分析 | 近1-2年 |
| T08 产品 | 官方文档/更新日志 | 最新 |

**防幻觉机制：**
- 事实必须附带 URL 来源
- 数据标注来源和获取时间
- 模型推断标注"待验证"
- 过期内容标注版本差异

  ↓ 收集信息 → 类型识别 → 输出 pre-analysis.md → 用户确认

## 关键设计决策

### 1. 只规划不写正文

**决策**：本技能只生成规划和调研文档，不生成书籍正文内容。

**理由**：
- 专注职责分离，与写书技能（如 `huashu-book-pdf2.1`）形成上下游关系
- 规划阶段需要大量调研和分析，独立处理可避免上下文混乱
- 用户可以在确认后调整方向，避免返工

### 2. 14类书籍类型体系

**决策**：建立覆盖全面的14类书籍类型识别体系。

**理由**：
- 不同类型书籍的调研维度、写作风格、读者预期差异巨大
- 预定义类型模板确保调研的系统性和完整性
- 支持跨类型组合（T14综合型），适应复杂主题

**权衡**：14类覆盖较广，但可能存在边界模糊的情况。处理方式：
- 自动识别后告知用户，支持手动调整
- 跨类型时组合多套模板，去除重复维度

### 3. 渐进式文件加载

**决策**：参考文件在对应流程步骤中按需加载，不一次性全部读取。

**理由**：
- 节约Token消耗，避免上下文溢出
- 各阶段关注的参考内容不同，按需加载更高效
- 符合"简单至上"原则

### 4. PROJECT.md 自包含设计

**决策**：PROJECT.md 的"信息来源"列直接写入调研结论摘要，而非仅写文件路径。

**理由**：
- 确保 PROJECT.md 是自包含文档，可独立阅读
- 下游写书技能无需额外读取调研文件即可获取关键信息
- 提高文档的可用性和可移植性

### 5. 可信度分级体系

**决策**：调研内容按 A/B/C/D 四级进行可信度分级。

**理由**：
- 帮助写书技能判断信息的可靠程度
- A级（官方文档/论文）作为核心依据，D级（未验证观点）仅作为线索
- 避免将未验证信息写入正文

## 使用说明

### 触发场景

用户通过以下场景触发本技能：
- "书籍规划"、"写书大纲"、"生成书籍计划"
- "BOOK_PLANNER"、"book planner"
- "书籍维度分析"、"生成PROJECT"、"书籍蓝图规划"

### 典型使用流程

```bash
# 1. 用户提供主题（可以是简单描述或上传材料）
# 示例："帮我规划一本关于 Kubernetes 运维的书籍"

# 2. 系统自动执行：
#    阶段0 → 识别为 T01 新技术学习类
#    阶段1 → 8-10个维度调研，生成 research/*.md
#    阶段2 → 生成完整的 PROJECT.md
#    阶段3 → 输出精简版大纲等待用户确认

# 3. 用户确认后，PROJECT.md 状态标记为：
#    ✅ 已确认，可交付写书技能使用

# 4. 下游写书技能（如 advance_book_creator）读取 PROJECT.md 开始写作
```

### 与其他技能的协作关系

```
用户输入主题
     ↓
book-planner ──→ PROJECT.md（规划文档）
     ↓
advance_book_creator / huashu-book-pdf-v2 ──→ 读取 PROJECT.md
     ↓
开始调研 → 规划 → 写作 → 构建 → 输出产物
```

### 网络搜索策略配置

按类型自动选择搜索策略，示例：

```
T01 新技术类：
  关键词示例："Kubernetes 生产环境最佳实践 2025 2026"
  英文补充："Kubernetes production best practices"
  site限定：site:kubernetes.io site:github.com

T08 产品手册类：
  关键词示例："产品名称 官方文档 更新日志 2025"
  英文补充："Product name changelog release notes"
  site限定：官方文档站点
```
