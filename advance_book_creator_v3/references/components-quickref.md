# lite 组件速查表（唯一规范）

> **核心原则**：正文永远是纯 Markdown，组件有专用 Markdown 语法。**不写任何 HTML 标签**（图形除外）。
> 组件结构由构建时转换器生成，写作者无需关心 CSS 类名。

---

## 语法总表

| 你要表达的内容 | 写法 | 说明 |
|---------------|------|------|
| 要点、结论、建议 | `> [!TIP]` | 提示块（主题强调色，默认主题为朱砂批注色） |
| 警告、风险、禁忌 | `> [!WARN]` | 警告块（玫瑰红） |
| 参考、来源、备注 | `> [!NOTE]` | 信息块（青色） |
| 重要概念、关键机制 | `> [!IMPORTANT]` | 紫色强调块 |
| 操作步骤（2步以上） | `:::steps ... :::` | 步骤卡片，内部是列表 |
| 好坏对比、方案选型 | `:::compare ... :::` | 红绿对比卡片 |
| 流程图、架构图 | 内嵌 SVG | 直接写 `<svg>` 标签 |
| 图片 | `<figure>` | 外部图片引用 |
| 术语强调 | `**粗体**` | 原生 Markdown |
| 文件树/目录结构 | ` ```text ` 代码块 | 原生 Markdown |

> 转换器同时接受 `[!INFO]`/`[!WARNING]`/`[!CAUTION]` 别名（分别等同 `[!NOTE]`/`[!WARN]`/`[!WARN]`），推荐统一使用上表 4 种。

---

## 1. 提示块（Callout）

**语法**：GitHub Alerts 风格引用块。首行 `[!类型]` 后可跟自定义标题，正文行以 `>` 开头，**正文内可用 Markdown**（粗体、行内代码、链接）。

```markdown
> [!TIP]
> 本章最重要的三个结论：**先设计后编码**、小步提交、持续验证。

> [!WARN] 版本兼容性
> 此配置在 3.x 以下版本会失败，运行 `npm ls` 确认版本。

> [!NOTE]
> 数据来源：2025 年官方基准测试报告。
```

| 类型 | 默认标题 | 典型场景 |
|------|---------|---------|
| `[!TIP]` | 核心要点 | 章节结论、最佳实践、建议 |
| `[!WARN]` | 注意 | 安全风险、常见坑、版本陷阱 |
| `[!NOTE]` | 参考 | 数据来源、背景补充 |
| `[!IMPORTANT]` | 要点 | 关键概念、必须理解的内容 |

---

## 2. 步骤块（:::steps）

**语法**：`:::steps` 与 `:::` 围起来的**普通 Markdown 无序列表**。每个列表项 = 一步；项内 `**加粗**` 会成为步骤标题；步骤编号自动生成。

```markdown
:::steps
- **安装依赖**：执行 `npm install playwright pdf-lib`
- **安装浏览器内核**：运行 `npx playwright install chromium`
- **验证安装**：新建 test.js 并运行 `node test.js`
:::
```

**步骤内放表格/代码块**：列表项下一行缩进书写即可，会自动并入该步骤：

```markdown
:::steps
- **配置参数**：按以下对照表设置
  | 参数 | 默认值 | 说明 |
  |------|--------|------|
  | batch.size | 16384 | 批次大小 |
- **重启服务**：使配置生效
:::
```

---

## 3. 对比块（:::compare）

**语法**：围栏内的列表，**第 1 条 = 左栏红（不推荐），第 2 条 = 右栏绿（推荐）**，第 3 条 = 中栏灰（备注，可选）。项内 `**加粗**` 会成为栏目标题（覆盖默认的"不推荐/推荐"）。

```markdown
:::compare
- **不推荐 ❌**：在循环里逐条发 SQL，网络往返次数等于行数
- **推荐 ✅**：使用批量写入，一次往返提交一批数据
- **备注**：单批建议控制在 500~5000 条之间
:::
```

---

## 4. 图形（唯一允许的 HTML）

> ⚠️ **闭合红线**：`<figure>`/`<svg>` 必须写闭合标签。未闭合的 figure 会让后续整章内容变成图注样式（实际事故：整页文字/代码全部居中）。转换器会自动补闭合并警告，但请不要依赖自愈。

**内嵌 SVG**（架构图/流程图首选）：直接写 `<svg>` 标签，**不要用代码块包裹**：

```html
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 960 520">
  <!-- SVG 内容 -->
</svg>
```

**外部图片**（封面装饰、数据图表，放 `assets/`）：

```html
<figure class="content-figure">
  <img src="../assets/chapter-01-diagram.svg" alt="架构图">
  <figcaption>图 1-1 架构总览</figcaption>
</figure>
```

**文件树**：用 ` ```text ` 代码块，不要用 HTML：

````markdown
```text
my-project/
├── src/
│   └── index.js
└── package.json
```
````

## ⚠️ 写作禁令

| 禁止写法 | 正确写法 |
|---------|---------|
| `<div class="callout ...">` / `<callout-tip>` | `> [!TIP]` |
| `<div class="step">` / `<div class="step-num">` | `:::steps` + 列表 |
| `<div class="compare">` / `<div class="compare-block">` | `:::compare` + 列表 |
| `<span class="tag-core">` | `**粗体**` |
| `<div class="flow">` | 内嵌 SVG 或 :::steps |
| `<div class="file-tree">` | ` ```text ` 代码块 |
| 自定义类名（step-card、flow-card 等） | 无需类名，转换器自动生成 |
| 组件内混写 HTML 语法（`<strong>`、`<ul>`） | 组件内就是 Markdown，直接写 |

> 门禁（check-md.js）会在构建时拦截上述 HTML 标签并阻断构建。
